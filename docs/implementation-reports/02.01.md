## 1. What was implemented

- **Migrations** `migrations/flowforge/0001_core.sql`, `0002_events_outbox_logs.sql`, `0003_workers_security.sql`, `0004_triggers_approvals.sql`:
  - Generated from the `00E` §2 DDL block, so they are byte-for-byte copies, then wrapped in `-- +goose Up` and a documented forward-only `-- +goose Down`.
  - `0001` adds the partial unique index `uq_tasks_original_key` (task §5), which is also added to `00E` §2.
  - `TestMigrations_VerbatimFrom00E` fails if a migration and `00E` §2 ever differ.
- **`migrations` package** (`migrations/embed.go`) embeds `flowforge/` and `marketdata/`. The `marketdata` set is empty until 05.03, and a README explains it.
- **`internal/persistence/migrate`**:
  - Functions: `Up(ctx, dsn, set) (int64, error)`, `Status(ctx, dsn, set) ([]MigrationStatus, error)`, `Version(ctx, dsn, set) (int64, error)` and `Latest(set) (int64, error)`, which needs no database.
  - Types: `Set` with `Flowforge`/`Marketdata`, `ErrUnknownSet` and `MigrationStatus`.
  - It uses the goose `Provider` over `database/sql` with the pgx stdlib driver. A Postgres advisory lock (polled every second, for up to 5 minutes) serialises concurrent runners.
  - An empty set only pings the database and reports version 0.
- **`cmd/flowforge-migrate`**: `flowforge-migrate [--db flowforge|marketdata] up|status`. DSNs come from `FF_PG_DSN`/`FF_MD_PG_DSN` through the new `config.Migrate` struct, and the CLI never prints a DSN. The logic sits in `run()` so it can be tested.
- **`internal/testutil`**: `ApplyMigrations(t, dsn, set) error` replaces the 01.02 stub, and `NewFlowforgeDB(t) *PG` returns a fresh database with every migration applied.
- **sqlc**: `sqlc.yaml` (postgresql engine, pgx/v5, schema from `migrations/flowforge`, queries from `internal/persistence/queries/`, output package `sqlcgen`), plus the `GetClusterState` query and the generated `internal/persistence/sqlcgen`.
- **Makefile**: `migrate-up`, `migrate-status` (with `DB=flowforge|marketdata`), and `sqlc`, which replaces the placeholder and refuses any sqlc other than v1.31.1. `sqlc-check` regenerates and fails if `sqlcgen` differs from what's committed or has untracked files.
- **CI**: new job `sqlc-drift` (installs sqlc v1.31.1, runs `make sqlc-check`).
- **Schema tests** (integration): up from empty, re-run no-op, version 4, up from each previous version, concurrent runners, objects (tables, indexes, sequence, columns, seed row), constraint violations, fencing sequence under 100 concurrent inserts.
- **Docs**: `docs/architecture/database.md`, which has the ER diagram, migration policy and how to add a migration, and is linked from `docs/development.md`. Also updated: the README quick start, `versions.md`, `docs/configuration.md`, `00E` §2 and §6, and an `00A` amendment.

## 5. Architectural decisions made during implementation

- **Migrations generated mechanically from `00E` §2** rather than retyped, and guarded by a test, so "verbatim" stays true.
- **goose `Provider` with a session locker**: concurrent migrators (several services or init jobs starting together) can't race on `CREATE TABLE`. The lock polls every second instead of goose's 5 s.
- **`database/sql` through the pgx stdlib driver**, because goose needs `*sql.DB`. The app keeps using pgx natively (sqlc `sql_package: pgx/v5`).
- **The `migrate` API returns its own `MigrationStatus` type**, so goose types don't leak into callers.
- **`Latest(set)`** is added for 02.04's `ErrSchemaBehind` check; it reads the embedded files, not the database.
- **The CLI connects as the application role** (`FF_PG_DSN`), so the tables are owned by `flowforge`, not the superuser.
- **sqlc defaults** (pgtype types for nullable columns and timestamps) are kept; 02.03 can add overrides when it writes real queries.

## 6. Deviations from the specification

1. **Clarification: an embed package at `migrations/embed.go`.** Task §4 puts the embed in `internal/persistence/migrate`, but `//go:embed` can't reference `../../migrations`. `migrations.FS` holds the files, and `migrate/embed.go` selects the set. `migrations/marketdata/README.md` exists because an empty directory can't be embedded.
2. **Clarification: the `testutil.ApplyMigrations` parameter is now a set name.** The 01.02 stub was `(t, dsn, dir string) error`; the task specifies `(t, dsn, set)`. The types and arity are unchanged. `ErrMigrationsUnavailable`, the stub's temporary sentinel, is removed, and its two tests now test the real behaviour as a separate suggested commit (`00C` §11). Nothing else used them.
3. **Clarification: `config.Migrate`** (in `internal/config`, owner 01.03) carries `Common` and both DSNs. `config.API` would also demand `FF_ADMIN_BOOTSTRAP_KEY` in prod. It reads no new variable; `00E` §6 now lists `flowforge-migrate` under "Used by" for the two DSNs.
4. **Compatible extension (required by the task): `uq_tasks_original_key`** in `0001` and `00E` §2, with the `00A` amendment "ADR-008 / ADR-014 — 02.01".
5. **Clarification: `make sqlc-check`** (the drift check, task §4) also fails on untracked generated files, not only on a `git diff`, so a newly generated file that was never committed is caught.
6. **Clarification: `make migrate-up` and `migrate-status` take `DB=`** (default `flowforge`) rather than running both sets, so they work when only the `core` profile is up.
