## 1. What was implemented

- **`internal/workflow/model`**:
  - `Definition`, `TaskDef`, `RetryPolicy`, `Concurrency`.
  - Typed enums with the exact `00E` §2/§3 values: `TaskStatus`, `AttemptStatus`, `RunStatus`, `RunIf`, `OnFailure`, `RetryStrategy`, with list functions.
  - `Decode([]byte)`: strict (`DisallowUnknownFields`, no trailing data, ≤ 512 KiB). Absent fields get the explicit `Default*` constants; explicit values, zeros included, are kept so validation can reject them.

  - `Validate` / `Validator{ValidateExpr, Refs}.Validate` returns every issue, sorted by (task ID, code, message), with the 13 stable codes of task §5 and a concrete cycle `Path`.
  - Graph helpers in O(V+E): `TopoOrder` (`ErrCycle`), `Ancestors`, `Roots`, `Children`. Cycles are found with Kahn's algorithm, and one cycle is extracted from the leftover nodes.
- **`internal/workflow/statemachine`**:
  - Task, attempt and run transition tables as data, identical to `00E` §3.1–3.3: `Can*Transition`, `*Transition` (an `INVALID_STATE` error wrapping `ErrInvalidTransition`), `IsTerminal*`.
  - The `00E` §7 event types, and `TaskTransitionEvent` / `AttemptTransitionEvent` / `RunTransitionEvent`.
  - `EvaluateReadiness` (`Wait`/`Ready`/`Skip`, with the `ExprEvaluator` interface and `ErrNoEvaluator`) and `DeriveRunStatus` with the handled-failure rule.
  - `NextRetryDelay`: fixed or exponential, capped, with ±jitter from an injected seeded `*rand.Rand`.
- **Docs**: `docs/architecture/workflow-semantics.md` (definition format, defaults, issue codes, Mermaid state diagrams for task/attempt/run, `run_if`, the retry formula, the handled-failure rule), linked from `README.md`.

## 5. Architectural decisions made during implementation

- **Wire structs with pointer fields in `Decode`**, so "absent" (gets the default) and "explicit zero" (kept, then rejected by `Validate`) differ. Without this, `"max_attempts": 0` would silently become 1.
- **`dag.Validator` struct instead of a package-level hook variable.** It carries `ValidateExpr` and `Refs` for 03.06 without global state (`00C` §8); `dag.Validate` is the zero-value shortcut.
- **One `CYCLE` issue with a concrete, normalised path** (rotated to its smallest ID), so the output is stable across task order.
- **Transition tables as read-only package-level maps** (data, per task §5), like the compiled regexps; nothing writes them.
- **`EvaluateReadiness` takes the evaluator as an argument and returns an error**, so `run_if: expr` without an evaluator fails loudly instead of being skipped.
- **`DeriveRunStatus` treats `CANCELLED` tasks as unhandled**, because 00E §3.3 counts only SUCCEEDED/SKIPPED (or handled failures) as success. Deliberate run cancellation is decided from run flags before the call.

## 6. Deviations from the specification

All are clarifications (`00C` §2.4):

1. **The expression field is `run_if_expr`** in the definition JSON. 00E §3.5 shows only `run_if`; the name matches the `workflow_tasks.run_if_expr` column.
2. **Bounds and defaults the documents leave open:**
   - Default task timeout 3600 s.
   - Workflow `timeout_seconds` 0 (none) to 604 800 s (7 days).
   - `concurrency.max_parallel_tasks` 0 (no limit) to 500.
   - Retry `initial_delay_ms` 0 to 24 h, and `max_delay_ms` ≥ initial and ≤ 24 h.
   - Default retry 1 attempt, fixed strategy, 1 s initial, 60 s max, multiplier 2, jitter 0.
   - Workflow name pattern `^[a-z][a-z0-9_-]{0,127}$`, and task `type` at most 128 characters.
3. **Extra `INVALID_RUN_IF` checks:** `on_failure` on a task without dependencies (it could never run), and `run_if_expr` set without `run_if: expr`.
4. **Names:** `TaskTransitionEvent` (singular; the task's sketch says `TaskTransitionEvents` but it returns one event), plus `AttemptTransitionEvent` and `RunTransitionEvent`. `DeriveRunStatus(tasks, onFailure model.OnFailure)` and `EvaluateReadiness(task, deps, eval)` spell out the task's "policy" and "injected evaluator".
5. **Event gaps in 00E §7:** attempt `RUNNING → CANCELLED` has no event type, so `AttemptTransitionEvent` returns `""` (the task's `task.cancelled` covers it). `NEEDS_ATTENTION → RUNNING` maps to `run.resumed`.
6. **`Decode` returns `PAYLOAD_TOO_LARGE` for bodies over 512 KiB** (FR-SEC-05), and `INVALID_ARGUMENT` for malformed JSON.
