## 1. What was implemented

- **`internal/stream/source`:**
  - **The interface:** `Source` (`Next(ctx) (domain.Tick, error)`; `io.EOF` at the end, `*ParseError` for an unreadable row).
  - **Event ids:** `EventID` (00E §7: sha1 of `source|symbol|sequence|event_time_ns`).
  - **`Synthetic`:**
    - a geometric random walk in integer cents per symbol, from a PCG seeded with `(seed, GeneratorVersion)`;
    - `simulated` or `realtime` clock;
    - injection of dup, late, out-of-order, invalid and gap (`ParseInject`);
    - `LastKind` and `Counts`.
  - **`FileSource`:** CSV with a header, or JSON lines, via `Open` or `NewFileSource`. Bad rows are reported with their line numbers, and the read continues.
- **`internal/stream/producer`:**
  - **`Producer.Publish`:**
    - validates each tick with `domain.Validate` plus `envelope.v1` (which checks `market_tick.v1`);
    - sends valid ticks to `market.ticks`, keyed by symbol;
    - sends rejects to `market.invalid` with a reason header and a `market_invalid.v1` payload (`schema_invalid` when only the schema fails), or to `market.ticks` with `AllowInvalid`.
  - **`Run`:** bounded batches, a count limit, and a summary.
  - **Metrics:** `flowforge_producer_events_total{result}` and `flowforge_producer_publish_latency_seconds`.
- **`cmd/flowforge-producer`:**
  - flags `--file --symbols --seed --rate --clock --start --duration --count --inject --batch --allow-invalid`;
  - `/metrics` on `FF_PRODUCER_HTTP_ADDR`;
  - a JSON summary;
  - exit codes 0/1/2.
- **Fixtures:** `testdata/marketdata/sample_ticks.csv` and `.jsonl` (the same eight ticks), and the golden stream hash.
- **`docs/architecture/market-data-generator.md`:** flags, determinism, injection semantics, file formats and the producer.

## 5. Architectural decisions made during implementation

- **Integer-only generation:** prices are cents, and the walk step is an integer number of basis points. Floats would let an arm64 build (which may fuse multiply-add) and an amd64 build drift, and the golden hash would differ by platform.
- **Simulated runs end at now** by default, and must be bounded, so every tick passes the future and retention checks.
- **Late and out-of-order ticks** are placed behind the *latest event time emitted*, so their lateness is exact (late beyond the 30 s allowed lateness, out-of-order within it). Duplicates copy one of the last 64 good ticks.
- **One validation call per tick:** `envelope.v1` checks `market_tick.v1`. A tick that is domain-valid but schema-invalid (size 0) is rejected as `schema_invalid`.
- **Producer topics are overridable** (`Options.TicksTopic`/`InvalidTopic`), so integration tests use their own topics.

## 6. Deviations from the specification

| Deviation | Kind | Reason |
|---|---|---|
| `event_id = sha1(source\|symbol\|sequence\|event_time_ns)`, 40 hex chars (the task: `sha256(…)[:32]`) | Clarification (human-confirmed) | 00E §7 outranks the task file |
| `market_invalid.v1`'s `source_topic`, `source_partition` and `source_offset` made optional by editing v1 in place | **Human-approved exception** (`00A` amendment) | A producer reject was never on a topic; v1 had no producer or consumer yet |
| `--speedup` not implemented | Clarification | Simulated mode already runs as fast as the broker allows; a paced replay speed is not needed by 05.03's tests (docs §Limitations) |
| `gap_windows` is a per-window chance (`gap=1%`), not a count | Clarification | Fits the percentage-based `--inject` syntax |
| `Source` is pull-only (`Next`); there is no channel-based `Run` on the source | Clarification | The task offers either; `producer.Run` drives it |
| New config `FF_PRODUCER_HTTP_ADDR` (`:8084`) beside the task's `FF_PRODUCER_RATE` | Compatible extension (00E §6) | The metrics need an endpoint in long-running mode |

## 7. Known limitations / follow-ups

- **Retention limit on history:** history older than the 14-day tick retention is rejected as `too_old`, so the bundled fixtures load as all-rejected once they are a fortnight old. They are for parsing tests. A `--rebase` to shift times is a possible follow-up.
- **Real-time accuracy:** realtime event times are the scheduled times, not send times.
