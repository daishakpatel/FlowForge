## 1. What was implemented

- **Snapshots and compaction** (`internal/raftkv/node/snapshot.go`, `ready.go`):
  - the automatic trigger (04.02) now takes `FF_RAFT_SNAPSHOT_ENTRIES` and `FF_RAFT_SNAPSHOT_TRAILING`;
  - `SnapshotNow` and `CompactNow` run on the loop;
  - the node tracks its first index;
  - `node.Status` gains `State`, `SnapshotIndex`, `FirstIndex` and `Peers` (the leader's view: match index and reachability).
- **Wiped-node support** (`node.step`): a heartbeat whose commit index is past the node's log is capped at the node's commit. Without the cap, a node restarted with an empty data directory under its old id panics in the raft library. Recovering it then needs a leadership transfer, which is documented in the runbook.
- **Metrics** (`node/metrics.go`): `flowforge_raft_snapshot_total`, `_apply_duration_seconds` and `_leader_changes_total`. `_peer_unreachable{peer}` is exported as 0 for every peer from the start.
- **Server** (`server/cluster.go`, `server/admin.go`):
  - `Cluster.Status`: role, peers with lag, the state hash at an applied index (`fsm.StateHashAt`), snapshot and first index, uptime;
  - `Cluster.Health`: `READY` or `NOT_READY` (a known leader, and applied within 100 entries of the leader's commit, which the node records from appends and heartbeats as `Status.LeaderCommit`);
  - the `Admin` service (`TransferLeader`, `SnapshotNow`, `Compact`), behind a bearer token compared in constant time.
- **Proto** (`kv.proto`): additive fields, plus the `Admin` service and its messages; regenerated with `make proto`.
- **Config** (`config.Raft`): `FF_RAFT_SNAPSHOT_ENTRIES` (10 000, at least 50), `FF_RAFT_SNAPSHOT_TRAILING` (1 000, below the entries) and `FF_RAFT_ADMIN_TOKEN` (a secret; empty disables admin).
- **Binary** (`cmd/flowforge-raft/admin.go`): the subcommands `status`, `health`, `dump-state-hash`, `transfer-leader`, `snapshot-now` and `compact`. The token comes from the environment.
- **Packaging:**
  - `deploy/docker/Dockerfile.raft`: multi-stage, distroless, non-root;
  - Compose `raft-1..3` (profiles `raft` and `full`) with fixed ids, volumes and healthchecks; clients on host `7001`–`7003`, peers internal on `7100`;
  - Make targets `raft-up`, `raft-down`, `raft-status`, `raft-logs`, `raft-kill N=`, `raft-restart N=`;
  - `scripts/dev/raft-smoke.sh`, plus the `compose`-tagged Go test `test/integration/raft`.
- **Docs:** `docs/architecture/raft-operations.md` and `docs/runbooks/raft-quorum-loss.md` (initial).

## 5. Architectural decisions made during implementation

- **Ports follow 00E:** the client port inside the container is `7000` (00E §6 `FF_RAFT_ENDPOINTS=raft-N:7000`), published as host `7001`–`7003`. The peer port is `7100`, never published.
- **Admin is a separate gRPC service on the client port,** gated by a bearer token. `status`, `health` and `dump-state-hash` need no token.
- **A wiped node keeps its id.** The heartbeat cap keeps it alive, and a leadership transfer gets it the snapshot. Automatic detection was tried and removed (§3).
- **Health is stricter than in 04.04:** it requires a known leader and an applied index within 100 entries of the leader's commit index. It isn't measured against the node's own commit, which a wiped follower's short log holds down; the review caught that (§3).

## 7. Known limitations / follow-ups

- **Wiped node: not safe in general (code review finding).** Raft assumes a node never forgets its log or its vote. Until a wiped node catches up, a committed entry may live on one node only, and the wiped node can vote twice in a term. Either can lose a committed write. 04.06 keeps the node alive (the heartbeat cap) and documents a guarded last-resort procedure: one node, a live leader, the other follower at lag 0, then a transfer and waiting for READY. The safe fix is remove-and-add with dynamic membership (FR-RAFT-11).
- **Heartbeat cap and unstable entries (review nit, accepted):** the cap compares against the durable last index. If a tick drains an append and a heartbeat together, the heartbeat's commit is withheld until the next one, about one tick later.
- **No TLS or auth** on the client and peer ports until 09.01. The admin token travels in plaintext. Image digests and hardening are 09.02's.
- **`Status` computes the state hash** over the whole state on each call; it is for operators only.
- **The Compose test needs Docker** and runs only through `scripts/dev/raft-smoke.sh`. CI wiring is a follow-up for 09.x.
- **Defects found in earlier tasks:** 04.02's node panics on a heartbeat past its log after data loss. Fixed with the cap (§6); not a defect for nodes that keep their data.
