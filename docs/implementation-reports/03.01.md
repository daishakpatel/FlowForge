## 1. What was implemented

- **Protocol:**
  - `proto/worker/v1/worker.proto` (00E §8) with the `WorkerService` RPCs `Register`, `Heartbeat`, `PollTask`, `CompleteTask`, `FailTask`, `ShipLogs` (client stream of `LogLine`) and `Deregister`.
  - `buf.yaml` (STANDARD lint plus one scoped exception for 00E's `LogLine` name; FILE breaking rules) and `buf.gen.yaml` (local, pinned plugins).
  - Generated Go in `internal/gen/proto/worker/v1`.
  - Make targets `proto` (checks the pinned buf, protoc-gen-go and protoc-gen-go-grpc versions, then lints and generates), `proto-check` (drift) and `proto-breaking` (`buf breaking` against `origin/main` once it has protos). A CI job `proto` runs both checks.
- **gRPC server:**
  - `flowforge-api` serves `WorkerService` on `FF_API_GRPC_ADDR` with a 4 MiB message cap. On shutdown it stops gracefully, bounded by the 30 s drain.
  - `workerapi.Interceptors` (unary and stream) handle:
    - request id (`x-request-id` header plus log fields);
    - panic recovery;
    - auth: `auth.VerifyToken`, role `worker` only, otherwise `UNAUTHENTICATED`/`PERMISSION_DENIED`;
    - error mapping: `apperrors.GRPCCode`, plus `ErrorInfo{reason: code, domain: flowforge.dev}`;
    - one log line per call;
    - `flowforge_grpc_requests_total{method,code}` and `flowforge_grpc_request_duration_seconds{method}`.
- **`workerapi.Service`:**
  - **`Register`:** validates the id regex, types, queues and capacity 1–1000; upserts `worker_observations` through `LeaseProvider.Register`. A live id held by another key is `CONFLICT`.
  - **`Deregister`.**
  - **`PollTask`:**
    - One short claim transaction: `ClaimQueuedTasks` (`FOR UPDATE OF t SKIP LOCKED`, the worker's registered types and queues, `available_at <= now`, run not `PAUSED` and not cancel-requested).
    - For each task, `TaskRepo.Transition` `QUEUED→RUNNING` (`attempt_count+1`, `task.started`), then `AttemptRepo.Create` (`attempt_count+1`, fencing token from the sequence, `deadline_at`, key `task_id:n`, `task.attempt.started`).
    - Long poll up to `wait_ms` (default 10 s, max 30 s) on the `LISTEN ff_task_queued` `Waker`, with a 1 s fallback re-check. It holds no connection while waiting and honours cancellation.
  - **`CompleteTask`/`FailTask`:**
    - The fencing is the conditional `UPDATE` in `AttemptRepo.Transition`; no row means `STALE_ATTEMPT` and increments `flowforge_stale_attempt_rejections_total`.
    - Then `OutcomeHandler.OnAttemptFinished` runs in the same transaction.
    - A result over 256 KiB fails the attempt (`RESULT_TOO_LARGE`, non-retryable) and answers `PAYLOAD_TOO_LARGE`.
    - Failure messages are redacted and capped at 4 KiB.
  - **`Heartbeat`:** updates `last_heartbeat_at` for (id, token) pairs still RUNNING on this worker (one SQL statement). The rest are returned as `stale_attempt_ids`. It renews the lease and returns `cancel_attempt_ids` from the `CancelSource`, plus `lease_ttl_ms` and `server_time`.
  - **`ShipLogs`:**
    - Per attempt: the token must match and the attempt must belong to one of the caller's workers.
    - `logging.Redact` is applied to messages and fields.
    - Lines over 8 KiB are truncated with `…[truncated]`.
    - 1000 lines per attempt, then one `WARN log limit reached` marker, and the rest are dropped.
    - Inserts are batched with COPY, ≤ 100 per transaction.
- **Seams** (`seams.go`):
  - `OutcomeHandler`, with the default `TerminalOutcomeHandler` (no retries);
  - `LeaseProvider`, with `PGLeaseProvider` (`lease_pg.go`: `last_seen_at`, expiry `last_seen_at < now − FF_WORKER_LEASE_TTL`, API clock);
  - `CancelSource`, with `NoCancels`;
  - `AttemptOutcome` and `AttemptKind`.
- **Persistence:**
  - `queries/claim.sql` (claim, heartbeat touch), `workers.sql`, `logs.sql`.
  - `TaskRepo.ClaimQueued`, `AttemptRepo.TouchRunning`, `WorkerRepo`, `TaskLogRepo` (+ `pg` implementations), and `WorkerView`, `TaskLogView`, `WorkerRegistration`, `NewTaskLog`, `ClaimFilter`.
- **REST (viewer):**
  - `GET /api/v1/workers`: status `ACTIVE|LOST|DEREGISTERED`.
  - `GET /api/v1/attempts/{attempt_id}/logs?after_id=&limit=`.
  - Both are in the OpenAPI spec and the ACL table.
- **Docs:** `docs/architecture/worker-protocol.md`; `00E` §8/§11.1, a `00A` amendment, `versions.md`, `README.md`.

## 5. Architectural decisions made during implementation

- **One-statement heartbeat:** the heartbeat touch is a single SQL statement (`id = ANY(ids) AND fencing_token = tokens[array_position(ids, id)] AND status = 'RUNNING' AND worker_id = $w`). Stale detection is the set difference, with no per-attempt reads.
- **Ownership:** every worker-scoped RPC checks that the worker was registered by the calling key, so one worker key can't poll for, heartbeat or ship logs as another key's worker.
- **The waker** is one goroutine and one connection per API process, broadcasting by closing a channel. Waiters take the channel before claiming, so a NOTIFY during the claim is never lost.
- **A gRPC listener failure** cancels the process context, so the API never runs half-up.

## 6. Deviations from the specification

1. **`PollTaskResponse` is `repeated Task tasks`** (at most `free_capacity`), not `00E`'s "optional Task". The task's claim (`LIMIT $free`, "never more than `free_capacity` per poll") and 03.03's runtime need several. `00E` §8 is updated and the `00A` amendment is added. `HeartbeatResponse` also gains `server_time` and `stale_attempt_ids` (task §4).
2. **`ShipLogs` keeps `00E`'s `stream LogLine`;** `buf.yaml` excepts `RPC_REQUEST_STANDARD_NAME` for that one file. The proto package is `worker.v1`, matching its directory, as buf STANDARD requires.
3. **Clocks:** time comparisons use the API clock as SQL parameters (claim `available_at <= $now`, worker `last_seen_at`, heartbeats), as task §5 asks. The attempt deadline is computed by 02.03's `AttemptRepo.Create` with the database clock (ADR-021), the same host clock in practice; this is noted, not changed.
4. **Repository layout:** worker and log storage are `persistence` interfaces with `pg` implementations (`worker_repo.go`, outside §7), like every repository before them. `lease_pg.go` adapts `WorkerRepo` to `LeaseProvider`.
5. **The registering key's id** is stored in `worker_observations.metadata.key_id` (no column exists). It's used for the `CONFLICT` rule and for ownership checks.
6. **`TestQueries_OnlyTransitionsWriteStatus`** (02.03) now inspects only `UPDATE`s of `workflow_runs`, `workflow_tasks` and `task_attempts`, the ADR-020 state machines. `worker_observations.status` is not a state machine and is written by the worker upsert and release. This narrows an existing test, so it is its own suggested commit.
7. **New gRPC metrics** `flowforge_grpc_requests_total` and `flowforge_grpc_request_duration_seconds` (`00E` §11.1, compatible).
8. **`LISTEN ff_task_queued`** is one constant statement executed directly on the waker's connection (LISTEN can't go through sqlc); nothing is built from input.
9. **Logs pagination:** the logs endpoint's `next_cursor` is the `after_id` of the next page (the task specifies `after_id`, not `cursor`).
