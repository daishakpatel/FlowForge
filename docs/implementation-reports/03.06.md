## 1. What was implemented

- **Templates (`internal/workflow/template`).**
  - `Resolver.Resolve(config, Scope)` resolves `${run.input.<path>}`, `${tasks.<id>.result.<path>}` and `${tasks.<id>.status}` in string leaves, recursively through objects and arrays.
  - A string that is exactly one placeholder keeps the referenced JSON type; placeholders inside longer strings are interpolated as text.
  - Paths are dotted keys with `[n]` indexes.
  - A missing path, a task without a result, or a task outside the scope gives `*TemplateError{Path, Reason}`. A result over 256 KiB gives `ErrTooLarge`.
  - Only the task's ancestors are in scope.
  - `Refs(config)` extracts references for validation, and `Reader` is the shared lookup used by expressions.
- **Expressions (`internal/workflow/expr`).**
  - A lexer, a hand-written Pratt parser following the task's EBNF, and an evaluator.
  - Operands: numbers, strings, booleans, `null`, and paths (`tasks.x.status`, `tasks.x.result…`, `run.input…`). Operators: `== != < <= > >= && || !` and parentheses.
  - `&&` and `||` short-circuit. Type errors are evaluation errors. A missing value is `null`, and comparing values of different types with `==` gives false.
  - `Evaluator` implements `statemachine.ExprEvaluator`; `Validate` and `Refs` are the `dag` hooks.
  - Limits: 4096 bytes and a nesting depth of 64.
- **Validation.**
  - `dag.Validate` extracts config placeholders and, through the hook, expression references. Unknown or non-ancestor tasks, and malformed placeholders, are `INVALID_REFERENCE`.
  - The API's definition service installs the hooks: `dag.Validator{ValidateExpr: expr.Validate, Refs: expr.Refs}`.
- **Scheduler.**
  - `scheduler.TemplateResolver` replaces `IdentityResolver` in `flowforge-scheduler`. Resolution happens at READY → QUEUED, and a resolver error fails the task READY → FAILED with `INVALID_INPUT`, no attempt and no retry (the existing 03.02 path).
  - `expr.Evaluator` is wired as `DecisionLoop.Eval` and bound to each run's input through the new optional `RunBinder`.
  - `processRun` passes each task's head **ancestors** to readiness and to the resolver.
- **Rerun.**
  - `RunService.Rerun(ctx, RerunParams{RunID, TaskKeys, Reason, Actor}) ([]string, error)` and `RunService.Retry`.
  - REST: `POST /api/v1/runs/{run_id}/rerun` (`{task_ids?, reason}`) and `POST …/retry`, both `200 {run, task_ids}` and operator-only (OpenAPI and ACL).
  - In one transaction it requires a FAILED or NEEDS_ATTENTION run that is not being cancelled, then inserts a PENDING row superseding each target (FAILED, TIMED_OUT or CANCELLED) and each descendant head that did not succeed. The originals are untouched.
  - The run moves to RUNNING: `completed_at` is cleared and the workflow deadline restarts. The `run.resumed` event carries `reason`, `actor`, `superseded_task_ids` and `rerun_task_ids`, and the scheduler is woken.
  - Persistence: `queries/rerun.sql` (`InsertRerunTask`), `persistence.RerunRepo`, `pg.RunRepo.InsertReruns`, and `TransitionRun` clearing `completed_at` on a move to RUNNING.
- **History.** `GET /api/v1/runs/{run_id}/tasks` lists head instances by default (`RunService.HeadTasks`); `?include_superseded=true` lists every generation.

## 5. Architectural decisions made during implementation

- **One path syntax and lookup for both languages.** Templates and expressions share `template.ParseRef` and `template.Reader`, so a path means the same thing in both, and a missing path is either a `TemplateError` (templates) or `null` (expressions).
- **The scheduler passes ancestors.** Readiness and the resolver get each task's head ancestors, found by walking `depends_on` across the heads; this costs nothing extra. Ancestors are a superset of the direct dependencies, so `EvaluateReadiness` needs no change.
- **The run input reaches the evaluator through `RunBinder`.** It's an optional interface, so `statemachine.ExprEvaluator` keeps its signature.
- **Rerun planning is pure.** `planRerun` and `heads` work on the head rows read in the transaction and are unit-tested without a database. The original rows are only inserted against, never updated.
- **Concurrency without a new lock.** Two concurrent reruns are serialized by the run version (optimistic `Transition`) and the existing unique `(run_id, task_key, supersedes_task_id)` constraint.

## 6. Deviations from the specification

1. **Compatible extensions** (`00E` and the `00A` amendment):
   - the FAILED → RUNNING run transition, with `completed_at` cleared;
   - the `INVALID_REFERENCE` issue code;
   - the head-only default for `GET …/tasks`, plus `include_superseded`;
   - `run.resumed` gains `actor`, `superseded_task_ids` and `rerun_task_ids`;
   - `RunService.Reruns` and `persistence.RerunRepo`.
2. **Ancestors at the seams** (clarification). 03.02's `InputResolver` doc said "direct dependencies", but task §4 needs templates and expressions to read any ancestor and `run.input`. The seams now get ancestors, and `RunBinder` is added; no signature changed.
3. **A rerun without `task_ids`** reruns every FAILED and TIMED_OUT task, the same as retry (clarification: task §4 marks `task_ids` optional without saying what omitting it means).
4. **A rerun restarts the workflow deadline** (clarification). Without it, a run that failed on its workflow timeout would fail again on the next timeout pass.
5. **Rerun replaces only finished rows.** A descendant that is still running makes the rerun 409 (clarification; a run in NEEDS_ATTENTION could, after 06.06, have tasks still running).
6. **`!` binds looser than comparisons,** as the task's EBNF says (`not = ["!"] cmp`). So `!a == b` is `!(a == b)`; this is documented.
7. **Changed existing tests:**
   - `dag/validate_test.go`: a non-ancestor or unknown expression reference is now `INVALID_REFERENCE`, as task §4 asks, in two expectations; new template cases.
   - `transitions_test.go`: the `00E` copy gains FAILED → RUNNING; one event case.
   - `scheduler/fakes_test.go`: the fake store now copies `run_if_expr` and `config`, which no earlier test needed.
   - The scheduler and recovery harnesses now use the production `TemplateResolver` and `expr.Evaluator`; their configs have no placeholders, so the older tests behave the same.
8. **Files outside §7:**
   - `dag/issues.go`; `service/workflows.go` (hook installation);
   - `scheduler/process_run.go`, `loop_scheduler.go`;
   - `statemachine`, `events`, `persistence` (`repos.go`, `pg/rerun_repo.go`, `runs.sql`, `sqlcgen`);
   - `rest/{tasks,router,routes_acl}.go`, both `cmd` mains, `.golangci.yml`, and the test files in §2.

   All of them are needed to wire and contract-test the task.

## 7. Known limitations / follow-ups

- **Expression evaluation errors leave a task PENDING.** A type error at run time leaves the task PENDING, with a warning logged on every tick. Validation can't catch type errors, because results are only known at run time.
- **No escaping for `${`** in config strings.
- **Rerun takes no `Idempotency-Key`** (nor do 03.05's run-control POSTs). A repeat is rejected by the run-status check.
- **Kept succeeded descendants aren't re-evaluated** against a new generation's results.
- **Temporary stubs:** none. `IdentityResolver` remains as a non-templating resolver; production no longer uses it.
- **Defects found in earlier tasks:**
  - **03.04 `TestTimeout_ServerDecidesAndLateReportIsStale` was flaky.** It failed once in the first full `make test-integration` run and passed in isolation, 5 more times, and in the second full run.
  - **Cause:** it set the fake clock to the database's `now()` *after* the claim and advanced it 0.9 s, assuming less than 100 ms passed between the claim and that read. Under full-suite load the "not timed out yet" check could already be past the 1 s deadline.
  - **Fix:** a test-only change, as its own commit. The clock is set from the attempt's `deadline_at` − 100 ms; the test then passed 10 times in a row.
  - **What I couldn't do:** the first run's failure message wasn't kept (the output was filtered), so the cause is inferred from the code rather than read from the log, and the failure couldn't be reproduced on demand.
