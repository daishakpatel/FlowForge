## 1. What was implemented

- **`cmd/flowforge-api`:**
  - Loads `config.API`, builds the logger, and refuses to start when `migrate.Version < migrate.Latest`.
  - Opens the pgx pool and wires repositories, services and the router.
  - Serves HTTP. On SIGTERM/SIGINT it drains in-flight requests for up to 30 s.
  - `/metrics` is served by the `obs` registry handler on the same router.
- **`internal/api/rest`:**
  - chi router with the middleware chain `RequestID → Recover → Logging (+ HTTP metrics) → BodyLimit(1 MiB) → Timeout(30 s, SSE path exempt)`, then `Auth` on `/api/v1`.
  - Error writer producing the `00E` §4 envelope (always with `request_id`, also in `X-Request-ID`). It maps oversize bodies to 413 and unreachable Postgres or the request timeout to 503 with `Retry-After`, and sanitizes everything else to INTERNAL.
  - Envelope-shaped 404/400 for unknown routes and methods.
  - The 11 `/api/v1` endpoints of task §4 plus `/healthz`, `/readyz` (Postgres ping and schema current; 503 with `Retry-After`) and `/openapi.json`.
- **`internal/api/service`:**
  - `WorkflowService.Create`: strict decode; an omitted version becomes latest + 1; `dag.Validate` → 422 with `details[]` (code, task_id, message); the normalized definition is stored; a duplicate is 409.
  - `WorkflowService.Get`, `GetByName`, `List`.
  - `RunService.Start(ctx, StartRunParams{…})`: input must be a JSON object of at most 256 KiB, and the key at most 128 characters. It replays an identical keyed request, returns 409 for a reused key, and handles the race (the loser re-reads and replays).
  - `RunService` read methods: `Get`, `List`, `Tasks`, `Events`, `Task`, `Attempts`.
- **`internal/api/auth`:**
  - `Authenticator` interface, `Principal`, `WithPrincipal`, `PrincipalFrom`.
  - `NewStub(disabled)`: the dev admin (`created_by = "dev"`) when `FF_AUTH_DISABLED=true`, otherwise 401.
- **Contract:**
  - `api/openapi/flowforge.v1.yaml` (OpenAPI 3.1, `ApiKeyAuth` bearer scheme, every route, every schema, strict response schemas), embedded through `api/openapi`.
  - `make openapi-check`: spec validation, route parity, and contract tests that validate every response and require every documented status code. Wired into the CI `integration` job.
- **Supporting changes:**
  - `RunRepo.GetByIdempotencyKey` and its sqlc query (the 02.03 follow-up).
  - `apperrors.Detail.Code` / `TaskID`.
  - `config.API.AuthDisabled` (`FF_AUTH_DISABLED`), rejected in prod.
- **Docs:** `docs/api/README.md`, the README quick start, `00E` §4/§6, a `00A` amendment, `docs/configuration.md`, `.env.example`, `docs/decisions/versions.md`.

## 5. Architectural decisions made during implementation

- **Contract tests are strict on purpose:**
  - Response schemas set `additionalProperties: false`.
  - A test helper validates every response the suite produces, using kin-openapi with JSON Schema 2020-12, the validator kin-openapi uses for OpenAPI 3.1 documents.
  - The suite fails if a documented response code is never produced.
  - `TestContract_RejectsViolations` proves the checker catches violations, so the guarantee isn't vacuous.
- **Normalized storage:** the stored definition is the decoded, defaulted definition re-encoded, so runs never depend on defaults changing later.
- **Validation is hand-written:** request validation happens in handlers and services. The spec documents it; there is no runtime spec-validation middleware, which keeps kin-openapi out of the binary.
- **Error classification at the HTTP boundary:**
  - `pgconn.ConnectError` → 503 `UNAVAILABLE`.
  - Context deadline → 503 `UNAVAILABLE`.
  - `http.MaxBytesError` → 413.
  - Unknown errors → sanitized 500.
- **Time comes from the injected clock:** request latency in the logging middleware uses the injected clock (`00C` §8.1), not `time.Now`.

## 6. Deviations from the specification

1. **`FF_AUTH_DISABLED`** is a new env var (compatible extension, `00A` amendment). The config loader has no bool type, so it's a `true|false` string validated with `oneof`. `crossCheck` rejects `true` with `FF_ENV=prod`.
2. **Error `details[]` entries** gain optional `code` and `task_id` (compatible extension, `00E` §4, `00A` amendment). The old `Detail{field, message}` couldn't carry the `details[].code=CYCLE` the task tests for.
3. **`RunRepo.GetByIdempotencyKey`** and its query were added to 02.03's package. It's an additive interface method that idempotent start needs; it was listed as a 02.03 follow-up.
4. **`scripts/dev/openapi-check`** is Go tests (`TestOpenAPI_*`, `TestContract_*`) run by the Make target. Task §7 allows "Go test or tool".
5. **`api/openapi/embed.go`** was added so the binary can embed the spec; `go:embed` can't reach outside its own package directory.
6. **`/metrics` is on the API router** (via the `obs` registry handler), not a separate listener. `00E` §9 lists `/metrics` among the API's routes, and no separate address is configured.
7. **Run tasks and attempts are unpaginated:** `GET /runs/{id}/tasks` and `GET /tasks/{id}/attempts` return everything, bounded by the repository row cap, with `next_cursor: null`. The events list is paginated on `workflow_events.id`.
8. **Status mappings for cases `00E` §4 doesn't name:**
   - A method not allowed is `400 INVALID_ARGUMENT`, since `00E` §4 has no 405.
   - An exceeded request timeout is `503 UNAVAILABLE` with `Retry-After`.
   - `/readyz`'s 503 uses the error envelope (FR-API-02: every non-2xx matches the schema).
9. **Omitted `version`** becomes latest + 1. Two concurrent creates of a new version of the same name race, and the loser gets 409 (documented).
10. **Graceful shutdown is tested through `serve()`** with the stop context that `signal.NotifyContext` provides in `main`, not by sending a real signal to the test process.
11. **"DB stopped" is simulated** by dropping the test's own database with `WITH (FORCE)`. The test container is shared, so stopping it would break parallel tests.
12. **Service structs are built as literals** with exported repository fields (`DefRepo`, `RunRepo`, …), not through constructors. Fields named after methods (`Tasks`, `Events`, `Attempts`) would clash.

## 7. Known limitations / follow-ups

- **`/readyz` opens a short goose connection** on each probe to read the schema version. That's fine at probe rates; cache it if probes get frequent.
- **The server's `WriteTimeout` is 35 s.** The SSE stream (03.07) will need it relaxed for that route, for example with `http.ResponseController`. `timeoutMiddleware` already exempts `/api/v1/events/stream`.
- **No runtime request validation against the spec;** handlers validate explicitly.
- **No generated API client yet** (07.01 owns it, `00C` §13).
- **RBAC,** the per-route role test and audit logging belong to 02.05. The routes are already in `00E` §9's role table.
- **Idempotency keys are never cleared:** the 24 h key retention is 03.07's job.
- **Test log noise:** `TestRecoverMiddleware_PanicIsInternalEnvelope` writes the logged panic to stderr, because the middleware falls back to `slog.Default()` without a request logger. It's cosmetic.
- **No temporary stubs** other than `auth.NewStub`, which is labelled and replaced by 02.05. **No defects found in earlier tasks. No skipped tests.**
