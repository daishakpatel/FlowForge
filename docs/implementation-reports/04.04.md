## 1. What was implemented

- **`cmd/flowforge-raft`** runs one node. It wires:
  - bbolt storage at `<FF_RAFT_DATA_DIR>/raft.db`;
  - the FSM, the Raft node and the gRPC peer transport (on `FF_RAFT_PEER_ADDR`);
  - the KV and Cluster services (on `FF_RAFT_CLIENT_ADDR`, with gRPC keepalive);
  - `/metrics`, `/healthz` and `/readyz` (on `FF_RAFT_HTTP_ADDR`).

  The cluster id is derived from the voter ids. Graceful shutdown on SIGTERM or SIGINT runs in four steps:
  1. **Readiness:** `/readyz` fails from the first moment.
  2. **Handoff:** a leader transfers leadership while still serving (best effort, ≤ 5 s).
  3. **Drain:** the client server drains (≤ 10 s).
  4. **Stop:** the node, the transport and the operational server stop, then the storage closes.
- **`internal/raftkv/server`** implements the `KV` and `Cluster` services.
  - **Writes:** only the leader accepts them. It stamps `ts_unix_ms` with its clock and passes the request's `(client_id, request_id)` through for FSM dedupe. It proposes inside `FF_RAFT_PROPOSAL_TIMEOUT` and the client's deadline, waits for apply, and maps the FSM result codes to statuses with ErrorInfo metadata `leader_hint`, `current_version` and `result_code`.
  - **CAS:** a mismatch is `succeeded=false`, not an error.
  - **Expire on touch:** a write touching a key whose lease the leader's clock says expired first proposes `LeaseExpire`, so writes see what reads see.
  - **LINEARIZABLE reads** (leader only): ReadIndex, then a re-check of leadership in the same term, then the leader's clock read after the ReadIndex judges lease expiry. The response carries `applied_index` (a lower bound) and `leader_now_ms`.
  - **SERIALIZABLE reads:** any node answers from local state, flagged `stale`.
  - **`List`:** pages with `start_key` → `next_key` (≤ 1000 keys and ~2 MiB per page) and leaves out expired lease-bound keys.
  - **`LeaseKeepAlive`:** refuses with `LEASE_EXPIRED` a lease the leader's clock says expired (holder's token only), after a ReadIndex, stamped at the same instant.
  - **Sweeper:** leader-only, every 500 ms, at most 64 `LeaseExpire` proposals per tick.
  - **Interceptor:** metrics, panic recovery, and logging of internal errors.
- **`internal/raftkv/client`**, re-exported as `pkg/client/coordination` with aliases for the proto types its API uses.
  - **Connections:** one gRPC connection per endpoint, with keepalive and a 100 ms to 1 s reconnect backoff.
  - **Leader:** a leader cache, updated only by leader-only calls. NOT_LEADER hints are mapped from node id to endpoint through `Cluster.Status`.
  - **Retries:** NOT_LEADER is redirected at once, or after a backoff when the hinted endpoint already failed in this call. UNAVAILABLE and NO_QUORUM are retried on the next endpoint after equal-jitter backoff (300 ms / 3 s defaults, ≤ 5 attempts, 10 s deadline by default). Nothing else is retried.
  - **Request ids:** every write carries `client_id` plus a request id made of a random per-client nonce and a counter, reused on that call's retries.
  - **Typed errors:** `ErrNotFound`, `ErrConflict` (with `CurrentVersion`), `ErrLeaseNotFound`, `ErrLeaseExpired`, `ErrInvalidArgument`, `ErrResourceExhausted` and `ErrUnavailable` (for a write, an unknown outcome).
  - **Methods:** `Get`, `List`, `Put`, `Delete`, `CAS`, `CASDelete`, `Txn`, `LeaseGrant`, `LeaseKeepAlive`, `LeaseRevoke`, `IncrCounter` and `Status`.
- **`internal/testutil/porcupine`:** a KV register model (Put, Get, and CAS on the version), nondeterministic for writes whose outcome is unknown; a `Recorder`; and `Check`, which keeps `history.json` and `visualization.html` when a check fails.
- **`test/fault/raft/linearizability_test.go`:** 8 clients, 4 keys, Put/Get/CAS, the leader killed every 2–4 s, for 60 s (5 s with `-short`), checked with Porcupine.
- **`internal/raftkv/kvtest`:** an in-process cluster of full stacks over loopback gRPC, with `Kill` and `Start`. The server, client and fault tests use it.
- **Supporting additions** (see §6):
  - `node.Node.TransferLeadership`, which picks a reachable follower, rejects non-voters and fails fast when no follower is reachable;
  - `fsm.FSM.ListFrom`;
  - the read-response proto fields;
  - `FF_RAFT_PROPOSAL_TIMEOUT` and `FF_RAFT_HTTP_ADDR`.

## 5. Architectural decisions made during implementation

- **Followers redirect instead of forwarding:** linearizable reads and writes get `NOT_LEADER` with the leader's node id (the task's "choose: return hint"). Nodes don't know each other's client addresses (`FF_RAFT_PEERS` carries peer addresses only), so the client maps the id to an endpoint by calling `Cluster.Status`. No config format changes.
- **Expire on touch:** a write touching a key bound to an expired lease first proposes `LeaseExpire` stamped with the same timestamp. This keeps 04.03's FSM semantics: `LeaseExpire` materializes expiry (ADR-005), and the FSM re-checks `expires_at ≤ ts`. Without it, a `CAS(expected=0)` right after a `Get` that said NOT_FOUND would fail until the next sweep.
- **Keep-alive on an expired lease:** checked on the leader after a ReadIndex and proposed with the same timestamp, so the check and the FSM agree on the instant.
- **Client backoff:** "equal jitter" (each wait in [c/2, c]) instead of full jitter, with 300 ms / 3 s defaults, so five attempts always outlast the 2 s maximum election timeout. Full jitter with a 50 ms base ran out of attempts within one test failover (see the debugging note in §7).
- **The KV test harness is a new package** (`kvtest`) rather than an extension of `nodetest`. nodetest drives nodes with manual ticks and a recording applier, while the server, client and Porcupine tests need full stacks over real gRPC on the real clock.

## 7. Known limitations / follow-ups

- **No authentication or TLS** on the KV and peer ports until 09.01 (ADR-015). Run them on a private network.
- **`List` sorts the whole key set on every page, under the FSM read lock** (code-review finding; 04.03's documented limit). It is fine at coordination scale. Follow-up: a sorted key index in the FSM.
- **Sweeper rate:** one `LeaseExpire` per lease, at most 64 per 500 ms. Reads hide expired keys and expire on touch covers writes in the meantime.
- **`Cluster.Status`** lists other members by peer address only; 04.06 extends Status and Health.
- **Review fixes without a dedicated test:** each is a one-line change, explained at the code.
  - the leader cache is no longer updated by Status and serializable calls;
  - leadership is re-checked after ReadIndex (a race window that can't be forced deterministically);
  - `/readyz` fails while stopping.
- **Debugging during the task** (`superpowers:systematic-debugging`):
  - **First failover runs exhausted the client's attempts.** Traced to two causes: followers still name the dead leader in their hints, and gRPC's reconnect backoff kept a restarted node looking down. Fixed with backoff before re-following a hint to a failed endpoint, a `ResetConnectBackoff` on that endpoint, shorter reconnect backoff, and equal-jitter backoff. A deterministic regression test was added: `TestClassify_HintToADownEndpointBacksOff`, which fails on the old rule.
- **Defects found in earlier tasks:**
  - **04.02, fixed:** `TestCluster_NoQuorumAppliesNothing` was flaky. Its stranded proposal could reach the loop after CheckQuorum stepped the leader down and fail with the definite `ErrNoQuorum`. It failed 38/40 against the committed code. The test now waits until the leader has appended the proposal (an outgoing MsgApp) before ticking. The assertions are unchanged. Separate suggested commit.
  - **04.02, follow-up:** `Propose` compares `len(data)` with `MaxSizePerMsg` without its 25-byte entry header.
  - **04.02, follow-up:** the snapshot assembler preallocates the unauthenticated `total_size` (≤ 64 MiB) per stream. Bound it when peer auth arrives in 09.01.
- **03.01, follow-up:** `cmd/flowforge-api` `TestRun_BootstrapIsIdempotent` flakes under full-suite load ("grpc: the server has been stopped": `Serve` racing a fast shutdown). Not touched here.
- **04.02, fixed:** `TestNode_ProposeWaitsForApply` asserted `Status().Applied` before the loop published it; it now waits (separate commit with commit 1).
- **Temporary stubs:** none.
