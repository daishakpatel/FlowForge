## 1. What was implemented

- **`internal/coordination`**, a client-side library over the Raft KV. No Raft server code changed.
  - **`KV`** (`kv.go`): the part of the KV client the library uses, with explicit parameters so a fake can implement it. `NewKV(*client.Client)` adapts the real client.
  - **`Elector`** (`elector.go`):
    - **Watch:** reads the leader key every `Renew`, jittered.
    - **Campaign** when the key is absent: `LeaseGrant(TTL)`, then `IncrCounter(/counters/scheduler_epoch)`, then a CAS of `/cluster/scheduler/leader` from absent to `{node_id, epoch, since_ms}` bound to the lease.
    - **Fence first:** `EpochFence.Activate(epoch, node)` must succeed before the term is announced. If it fails, the candidate revokes its lease and campaigns again after a backoff, with a new epoch.
    - **Renewal:** a keep-alive every `Renew`. `LEASE_EXPIRED` or `LEASE_NOT_FOUND` ends the term at once; other failures are retried until the local deadline.
    - **Ending a term:** at the local deadline, on shutdown or on a lost lease. The lease is revoked so a successor needn't wait out the TTL.
    - **Reading the leader:** `Current(ctx)` returns `LeaderInfo` or `ErrNoLeader`.
  - **`Gate`** (`gate.go`) implements `scheduler.Gate` (`IsLeader`, `Epoch`, `Done`, `Wait`), plus `Term()`, which reads the epoch and leadership together.
    - **Local conservative expiry:** `IsLeader` is false from `start of the last successful grant or keep-alive + TTL − SafetyMargin` (margin defaults to TTL/3), checked on every call. It holds even while the elector's goroutine is stuck.
  - **`EpochFence`:** the activation hook that 04.07 implements with `ClusterRepo.SetEpochIfGreater`.
  - **`WorkerRegistry`** (`registry.go`):
    - **`Register`:** validates the id, grants a lease and CASes `/workers/{id}` onto it. A worker id held by another API key is `ErrWorkerConflict`. A CAS whose outcome is unknown is re-checked before any cleanup.
    - **`Renew`:**
      - an expired lease is re-registered;
      - another instance's live lease is adopted;
      - a revoked or swept lease is `ErrNotRegistered`, so a renewal can't resurrect a deregistered worker;
      - any other failure returns the handle unchanged and is counted.
    - **`Handle`:** rebuilds a handle from the key alone, for stateless API instances.
    - **The rest:** `Deregister`; `List` (paged, linearizable reads); `Expired(known)` (known minus alive, sorted and deduplicated).
  - **`Fence`** (`fence.go`): `FenceFromLeader(gate)`, `Fence.Current(stored)` and `Fence.Supersedes(other)`.
  - **Metrics** (`metrics.go`): `ElectorMetrics` (`flowforge_scheduler_is_leader`, `flowforge_scheduler_epoch`, `flowforge_leader_changes_total`) and `RegistryMetrics` (`flowforge_worker_lease_renewal_failures_total`).
- **`internal/coordination/fake`:** an in-memory `KV` on a fake clock with the Raft KV's lease semantics: expiry hides keys, writes expire leases on touch, `LEASE_EXPIRED` vs `LEASE_NOT_FOUND`, and per-client partitions.
- **Defect fix in 04.03's FSM** (`internal/raftkv/fsm/lease.go`): keep-alive now sets `expires_at = max(expires_at, ts + ttl)` instead of `max(expires_at, ts) + ttl` (§6, §7).

## 5. Architectural decisions made during implementation

- **Explicit-parameter `KV` interface plus an adapter.** The real client takes opaque functional options that a fake can't read, so the interface spells out each parameter (task §6 step 1).
- **Fence before announce; failure gives the term up.** A failed `Activate` revokes the lease and re-campaigns with a new epoch, rather than holding the key unannounced. No one else could lead in the meantime.
- **Stateless registry.** A worker's heartbeats may reach any API instance, so the key's value stores the lease's fencing token and `Handle` rebuilds a handle from the key alone. A stale handle adopts the live lease rather than re-registering, which would make two instances ping-pong.
- **`Renew` re-registers only an expired lease.** A missing lease means `Deregister` revoked it, or the sweeper removed it, so `Renew` returns `ErrNotRegistered`. The API tier, which knows from Postgres whether the worker deregistered, decides whether to call `Register`. This keeps a heartbeat that races a graceful shutdown from resurrecting the worker.
- **The `scheduler.Gate` assertion sits in a test file,** so `coordination` doesn't depend on `scheduler`.

## 7. Known limitations / follow-ups

- **The single-leader guarantee assumes bounded clock-rate drift** between the scheduler and the Raft leader, within `SafetyMargin` per TTL. A GC pause longer than the margin, between `IsLeader` and a decision, can still let a deposed leader try; the Postgres epoch assertion rejects it (ADR-003). The end-to-end proof is 04.07 and 04.08's.
- **Every campaign uses up an epoch,** including lost ones and failed fence activations. Only monotonicity matters.
- **`Expired(known)` needs the known set** from Postgres (`worker_observations`), which 04.07 wires.
- **Defects found in earlier tasks:**
  - **04.03, fixed (separate commit):** keep-alive expiry accumulated a TTL per renewal. With the defaults (leader 10 s TTL renewed every 3 s; workers 15 s renewed every 5 s), a crashed scheduler leader or worker kept its lease for minutes or hours after a long run, blocking re-election and worker-loss recovery. Found with `superpowers:systematic-debugging` when `TestElector_StepsDownBeforeTheServerExpires` saw no takeover: the server-side expiry had run 13 s past the last renewal. The FSM test now fails on the old formula.
  - **04.04, test calibration:** `leaderWait` (5 s → 15 s), above.
  - **04.02, pre-existing flake:** `TestCluster_PartitionedLeaderStepsDownAndRejoins` failed once in the baseline `make test` and passed 20/20 alone. Not investigated further here; follow-up.
  - **04.01, pre-existing flake under load:** `TestBolt_CrashSafety`'s self-check failed once in `make test-integration` ("the child grew the log before only 18 of 50 kills"). It passed 3/3 alone, and `internal/raftkv/storage` is untouched here. Its timed kills need more log growth when the CPU is saturated. Follow-up.
  - **04.04, test calibration:** the read-after-write test's retry of `ErrUnavailable` calls (§6). Follow-up: leader churn of `kvtest`'s 10 ms tick under CPU saturation could be looked at with a coarser tick for the heavy tests.
- **Not unit-tested:** `Gate.Wait`'s wait on `Done` past the deadline, which avoids a busy loop. The behaviour is unchanged and a test can't observe a spin without timing; it is explained at the code.
- **Temporary stubs:** none. `EpochFence` has no production implementation until 04.07, by design.
