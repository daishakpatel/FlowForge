## 1. What was implemented

- **Loader** (`internal/config/loader.go`): `Load[T any](opts Options) (T, error)` walks the struct by reflection. Leaf fields carry `env:"…"`, `default:"…"` and `validate:"…"` tags; untagged struct fields, such as the embedded `Common`, are walked recursively.
  - Layers, later ones winning: tag default < YAML file from `FF_CONFIG_FILE` < environment. A set-but-empty variable counts as unset.
  - Supported types: `string`, `Secret`, `int`, `uint64`, `time.Duration`, `[]string` (comma-separated, trimmed).
  - The file is a flat YAML map of variable names to scalars. A key that no service struct reads is rejected; keys belonging to other services are accepted, so one file can serve every service.
  - `Options{Prefix, LookupEnv}`: `Prefix` names the file variable `<Prefix>_CONFIG_FILE` (default `FF`); `LookupEnv` defaults to `os.LookupEnv` and lets tests inject a map.
- **`Secret`** (`secret.go`): prints `***` through `fmt.Formatter` (every verb), `String`, `GoString`, `MarshalJSON`, `MarshalText` and `slog.LogValuer`. `Reveal()` is the only way to get the value.
- **Validation** (`validate.go`): rules `required`, `required_in_prod`, `positive`, `dsn`, `addr`, `url`, `oneof`. Cross-field rules: `FF_LEADER_RENEW < FF_LEADER_TTL/2` and `FF_WORKER_HEARTBEAT < FF_WORKER_LEASE_TTL/2`.
  - Parse and rule errors are all collected into one `*ValidationError{Fields []FieldError}`, where each `FieldError` has `Env` and `Msg`. Messages never contain the value.
- **`Redacted()`** on every service struct: a map from variable name to value for the startup log. Set secrets show as `***`, unset ones as `""`.
- **Service structs**, with defaults from `00E` §6: `Common` (`FF_ENV`, `FF_LOG_LEVEL`, `FF_LOG_FORMAT`, `OTEL_EXPORTER_OTLP_ENDPOINT`), `API`, `Scheduler`, `Worker`, `Raft`, `Processor`.
- **`.env.example`**: every variable in `00E` §6, grouped by service and commented, with dev-only values. The 01.02 entries are kept.
- **Drift guard** (`drift_test.go`): every `env` tag must appear in `.env.example` (as `NAME=`, commented or not), in `docs/configuration.md` and in `00E` §6.
- **Lint**: a forbidigo pattern `^os\.(Getenv|LookupEnv|Environ)$` applies everywhere except `cmd/**` (already exempt from forbidigo), `internal/config` and `internal/testutil` (only the env rule is lifted there). `make lint-selftest` now proves the ban fires.
- **Docs**: `docs/configuration.md` covers usage, precedence, the file format, validation rules, the variable table, secret handling and the lint rule. It's linked from `README.md` and `docs/development.md`.

## 5. Architectural decisions made during implementation

- **Own reflection loader instead of `caarlos0/env`.** The task allows either. The loader is about 200 lines, needs no extra dependency, and does the things a library would need wrapping for: reporting parse and rule errors together, using one parse path for every layer, and keeping values out of error text.
- **Flat YAML file keyed by variable name.** The same name works in the environment, the file, `.env.example` and the docs, so the drift guard covers the file format too, and an unknown key can be detected without a second naming scheme.
- **Unknown file keys are checked against every service's variables, not just the loading service's**, so a shared file works and typos are still caught.
- **Set-but-empty variables count as unset.** Compose writes `VAR=` for unset interpolations; treating that as "clear the value" would silently drop file values and defaults.
- **DSN check is a URL parse, not `pgconn.ParseConfig`.** `ParseConfig` reads `PG*` variables and `~/.pgpass`, which is a side effect at config time, and its errors can quote the DSN. URL form matches every DSN in `00E` §6.
- **DSNs are `Secret`s** because they carry passwords (`00C` §10.2).
- **Per-instance values have no defaults and are required** (`FF_WORKER_ID`, `FF_WORKER_QUEUES`, `FF_WORKER_CAPACITY`, `FF_API_GRPC_TARGET`, all `FF_RAFT_*` node variables), because `00E` §6 gives them none.

## 6. Deviations from the specification

All are clarifications (`00C` §2.4):

1. **`Options.Prefix` names the config-file variable** (`<Prefix>_CONFIG_FILE`). The task has both `Options{Prefix:"FF"}` and tags carrying the full `FF_…` name. Prefixing the tags would make `OTEL_EXPORTER_OTLP_ENDPOINT` (no `FF_` prefix, `00E` §6) impossible, so the tags keep full names.
2. **`FF_ENV` accepts `dev`, `test`, `prod`.** `00E` §6 named no values; this task uses `prod`. The allowed values are now in the `00E` §6 row. **Conflict:** task 09.01 writes `FF_ENV=production`. By the precedence in `00C` §2.12 (`00E`, then this task file), `prod` wins, and 09.01 must use it (§7).
3. **`FF_LOG_LEVEL` is one of `debug info warn error`, and `FF_LOG_FORMAT` one of `json text`.** `00E` §6 gives defaults only; these are the slog levels and the two slog handlers. 01.04 (logging) may rely on them.
4. **`FF_RAFT_NODE_ID` is a `uint64` and must be positive**, as the etcd Raft library requires for node IDs. The `FF_RAFT_PEERS` entry format is left to 04.02; the loader only splits the list.
5. **The YAML library `go.yaml.in/yaml/v3` v3.0.5** is used for the file layer. It isn't on the approved list in `00C` §10.3, but it replaces nothing on it. The standard library has no YAML, it was already in `go.sum`, and its licence is MIT + Apache-2.0. Recorded in `versions.md`.
6. **The env ban also covers `os.LookupEnv` and `os.Environ`**, which are the obvious ways around an `os.Getenv`-only rule. `internal/testutil` is exempt, as the 01.02 `00A` amendment requires.
7. **Files outside the task's list:** the lint self-test script and fixture, `go.mod`, the README and dev-guide links, `versions.md` and `00E` (all explained in §2).

5. **`Secret` fields must be exported**; `fmt` prints unexported fields raw. Documented on the type and in `docs/configuration.md`.
