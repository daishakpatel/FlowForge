## 1. What was implemented

  - `apache/kafka:4.1.1`, single broker in KRaft mode, with a fixed cluster id and a `kafkadata` volume;
  - listeners: `kafka:9092` inside Compose, `127.0.0.1:19092` from the host (`FF_DEV_KAFKA_PORT`);
  - `auto.create.topics.enable=false`;
  - a healthcheck that asks the broker for its API versions.
  - **`PROFILE`:** `make dev-up` takes `PROFILE` (`make dev-up PROFILE=streaming`).
- **Topic bootstrap:**
  - **The catalogue:** `deploy/kafka/topics.yaml`, as data. It has the 00E §7 topics plus `flowforge.dlq`, each with partitions, replication factor, key, purpose, retention and cleanup policy.
  - **The command:** `flowforgectl topics ensure [-f file]`, run by `make topics`, through `internal/kafka.LoadTopics`, `Plan` and `EnsureTopics`. It creates missing topics. For an existing topic it only warns about different partitions, replication factor or configs; it never changes or shrinks one.
- **Event envelope and schemas:**
  - **The schemas:** `schemas/events/*.schema.json` (draft 2020-12, each with an example):
    - `envelope.v1`, which checks the payload of every known event type and version;
    - `flowforge_event.v1`;
    - the six workflow payload schemas `workflow_*.v1`;
    - `market_tick.v1`, `market_aggregate.v1`, `market_invalid.v1`.
  - **Embedding:** the `schemas` package embeds them; `schemas/baseline/` holds the published snapshots.
- **`pkg/events`:**
  - `Envelope[T]`, `Marshal`, and `Unmarshal` (which ignores unknown fields);
  - `Registry` (`NewRegistry`, `Names`, `Validate`), `ValidationError{Schema, Path, Reason}` and `ErrUnknownSchema`;
  - the schema-compatibility test against `schemas/baseline/`.
  - **`internal/events.Envelope`** is now an alias of `Envelope[json.RawMessage]`, so there's one envelope type. A contract test validates every recorded workflow event against `flowforge_event.v1`.
- **`internal/kafka` (franz-go):**
  - **Config:** `Config` (= `config.Kafka`: `FF_KAFKA_BROKERS`, `FF_KAFKA_CLIENT_ID`, and the `FF_KAFKA_SECURITY_PROTOCOL` placeholder, `PLAINTEXT` only until 09.01) and `NewAdmin`.
  - **`NewProducer`:** idempotent, `acks=all`, with bounded linger, batch size, buffer and deadlines. `Produce` is synchronous and injects the traceparent header.
  - **`NewConsumer`:** group member with manual commits. A polled batch keeps its partitions until the next `Poll`, and fetches are bounded. Methods: `Poll`, `Commit`, `Close`.
  - **Headers:** `HeaderTraceparent`, `WithTraceparent`, `TraceparentFrom`, `InjectTrace`, `ExtractTrace`, `Header`, `SetHeader`.
- **`internal/kafka/kafkatest`:**
  - `Start(t)` gives one shared `apache/kafka` container per test binary (or `FF_TEST_KAFKA_BROKERS`). Without Docker it skips, or fails when `FF_TEST_REQUIRE_DOCKER` is set.
  - `Broker.Config` and `Broker.Topic(t, partitions)`, a unique topic deleted at the end of the test.
  - `Name(prefix)`.
- **Docs:** `docs/architecture/event-schemas.md`, covering the envelope, schemas, compatibility rules, topic catalogue and retention rationale, Compose Kafka, the client, and testing.

## 5. Architectural decisions made during implementation

- **The envelope shape is 00E §7's**, the one the outbox already produces, not the task file's "§7.2" shape (§6).
- **One envelope type:** `pkg/events.Envelope[T]`; `internal/events.Envelope` is an alias.
- **One validation call per record:** `envelope.v1` maps each known `event_type` + `event_version` to its payload schema with `if`/`then`. An unknown type or version keeps any object payload, so older consumers accept newer producers.
- **Strict compatibility:** besides fields, any change to a validation keyword is breaking; only adding `enum` values is allowed.
- **Topic bootstrap never mutates** an existing topic; it only warns.
- **Consumers hold a polled batch's partitions until the next `Poll`** (franz-go `BlockRebalanceOnPoll`). A batch's `Commit` therefore always precedes any rebalance.
- **`kafkatest` runs the Compose image** as a generic container. The testcontainers Kafka module supports only Confluent's image.

## 7. Known limitations / follow-ups

- **No broker-side validation:** producers and consumers validate.
- **Strict compatibility test:** a change that only widens a keyword (for example a looser `pattern`) still needs a new version.
- **Listing lag:** a topic created or deleted moments ago may not be listed yet. `topics ensure` then warns that it wasn't compared; run it again.
- **Single dev broker:** replication factor 1, plaintext. Multi-broker settings and TLS/SASL come with 09.01 and 09.06.
- **`FF_KAFKA_CLIENT_ID` is read only by `config.Kafka`.** The Scheduler, Worker and Processor configs have no client-id field yet; the tasks that build their clients (05.04, 05.08) should set one.
- **Defects found in earlier tasks:** none new. 04.01's `TestBolt_CrashSafety` load flake (already a 04.05 follow-up) failed in two of three full runs here; giving its self-check more room under load remains a follow-up for 04.01's owner. The other first-run failures are in §3.
- **Temporary stubs:** none.
