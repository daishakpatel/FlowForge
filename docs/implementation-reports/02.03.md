## 1. What was implemented

- **`internal/persistence/pg` pool and transactions:**
  - `NewPool(ctx, config.Secret)` parses, connects and pings.
  - `TxManager.WithTx(ctx, opts, fn)` commits on nil and rolls back on an error or a panic, re-raising the panic. On `40001`/`40P01`, from `fn` or from commit, it reruns `fn` up to `MaxTxRetries` = 3 times, with jittered exponential backoff through the injected clock and seeded RNG. A cancelled context stops the retries.
- **sqlc queries** (`internal/persistence/queries/*.sql`, regenerated into `sqlcgen`):
  - definitions: insert, get, get by name+version, latest by name, keyset list
  - runs: insert, get, keyset list with status/workflow/since/until filters, conditional transition on `(id, status, version)`
  - tasks: bulk insert (`COPY`), get, list by run, list by run+status, conditional transition
  - attempts: insert, get, list by task, conditional finish on `(id, status, fencing_token)`
  - events: `workflow_events` insert, outbox insert, list by run
  - cluster_state: get, set-if-greater, `FOR SHARE` lock
- **Repository interfaces** in `internal/persistence` (`DefinitionRepo`, `RunRepo`, `TaskRepo`, `AttemptRepo`, `EventRepo`, `ClusterRepo`, `TxManager`) with Postgres implementations in `pg`.
- **Conditional transitions:**
  - `TaskRepo`, `RunRepo` and `AttemptRepo` `.Transition` check `statemachine.*Transition` before any SQL, then run `UPDATE … WHERE id AND status = From [AND version | fencing_token]`.
  - When the `UPDATE` matches 0 rows, a follow-up read tells NOT_FOUND apart from INVALID_STATE (task), INVALID_STATE/CONFLICT (run) and STALE_ATTEMPT (attempt).
  - A test fails the build if any other query writes `status`.
- **Event recording:**
  - `internal/events` has typed payloads and family constructors covering all 28 `00E` §7 types, plus the envelope.
  - `Recorder.Record(ctx, tx, ev)` inserts `workflow_events` and `outbox` in the caller's transaction. The topic comes from the event type, the key is the run id, and `correlation_id` is the request id when present, else the run id.
  - Every transition helper records its default event, or the caller's override.
- **`ClusterRepo`:**
  - `GetEpoch` and `SetEpochIfGreater` (a no-op unless the new epoch is higher).
  - `AssertEpoch(ctx, tx, epoch)` takes `FOR SHARE` and returns NOT_LEADER wrapping `persistence.ErrStaleEpoch` on a mismatch. Epoch 0 is unfenced mode.
- **`RunRepo.CreateWithTasks(ctx, tx, run, def)`** creates the run (with a workflow deadline from the database clock), one PENDING task per definition task in `dag.TopoOrder` order (dependencies, `run_if`, config, retry-policy JSON, timeout) and `run.created`, all in one transaction.
- **Read models:** `RunView`, `TaskView` (with `State()` for the statemachine rules), `AttemptView`, `DefinitionView`, `EventView`; opaque keyset cursors (`EncodeCursor`, `DecodeCursor`, `Page`).
- **Docs:** `docs/architecture/persistence.md`, linked from `README.md`.

## 5. Architectural decisions made during implementation

- **Interfaces in `persistence`, implementations in `pg`:** this matches the handoff's "repo interfaces + `pg` implementation" and lets §5's `func (r *TaskRepo) Transition` exist as written.
- **Multi-row writes take a `pgx.Tx`:** a status change can't be committed without its event, and the compiler enforces it.
- **The database clock owns deadlines** (`deadline_at`, `available_at`, `started_at`, `completed_at`), per ADR-021. The injected clock stamps only envelope `occurred_at`.
- **Event payloads are one struct per family**, with seven constructors covering all 28 types. `Record` rejects a payload from the wrong family, an unknown type or a missing run id. Error messages never go into payloads.
- **Run transitions also check `version`:** a stale read is CONFLICT, as the §4 query list requires (`(id,status,version)`).

## 6. Deviations from the specification

All clarifications (`00C` §2.4); none changes a `00E` contract.

1. **Repository files** are `internal/persistence/pg/*_repo.go`, not `internal/persistence/*_repo.go` (§7). Go can't have both §4's `TaskRepo` interface and §5's `TaskRepo` struct in one package; the handoff list says "`pg` implementation".
2. **`Transition` signature:** the §5 params-struct contract is used, not §4's positional `(ctx, q, id, from, to, mut)`.
3. **`Querier` vs `pgx.Tx`:** §4 says all mutating methods accept a `Querier`. Methods that write more than one row (`Transition`s, `CreateWithTasks`, `AttemptRepo.Create`, `AssertEpoch`, `Record`) take a `pgx.Tx`, to enforce acceptance criterion 2. Single-statement writers (`DefinitionRepo.Create`, `SetEpochIfGreater`) take a `Querier`.
4. **`events.Record(q, Event)`** became `(*events.Recorder).Record(ctx, tx, Event)`. The recorder carries the injected clock, ID generator and producer name (`00C` §8.1), and `ctx` comes first (`00C` §8).
5. **Attempt finish failures** return STALE_ATTEMPT, not INVALID_STATE. `00E` §4 defines STALE_ATTEMPT for exactly this case, and `00E` outranks the task file (`00C` §2.12).
6. **`AssertEpoch` error:** the task names "`NotLeader`/`StaleEpoch`", but `00E` §4 has no `STALE_EPOCH` code. It returns NOT_LEADER wrapping the sentinel `persistence.ErrStaleEpoch`.
7. **Topics and keys for events `00E` §7 leaves open:**
   - `approval.*`, `worker.*` and `scheduler.leader_changed` go to `flowforge.workflow-events`.
   - The cluster events have no run, so they skip `workflow_events` (its `run_id` is `NOT NULL`) and are keyed by their aggregate id.
8. **Envelope `trace`** is omitted (`omitempty`) until tracing exists (08.01).
9. **`CreateWithTasks(ctx, tx, run, def)`** takes the decoded definition instead of prebuilt task rows, because §4 says the rows are "derived from the definition".
10. **`logging.Field(ctx, key)`** was added to the 01.04 package so `correlation_id` can use the request id that `logging.WithFields` stores (§5). It is an additive internal function, not a `00E` contract.
11. **`EventRepo`** is a read repository (`ListByRun`, for 02.04's events endpoint); writes go through `events.Recorder`.
12. **"Retry max 3"** means 3 retries, so at most 4 attempts.
