## 1. What was implemented

- **`proto/coordination/v1/command.proto`** (generated into `internal/gen/proto/coordination/v1/command.pb.go`):
  - **`Command`:** `{meta{client_id, request_id, ts_unix_ms}, op}`, where `op` is one of `Put`, `Delete`, `CAS`, `Txn`, `LeaseGrant`, `LeaseKeepAlive`, `LeaseRevoke`, `LeaseExpire`, `IncrCounter` or `NoOp`. It reuses kv.proto's request messages.
  - **Results:** the `ResultCode` enum and `CommandResult`.
  - **Snapshot payload:** `FSMState` with `StoredKey`, `StoredLease`, `StoredCounter` and `StoredDedupe`.
- **`internal/raftkv/fsm`:**
  - **`FSM`:**
    - `Apply(index, data) (*CommandResult, error)` (§4).
    - Every outcome, undecodable bytes included, is a deterministic result.
    - Indexes at or below the applied index are refused: the remembered result or `ErrAlreadyApplied`.
  - **Semantics** (`ops.go`, `lease.go`, `counter.go`):
    - **Keys:** versions, mod and create indexes, `expected_version`.
    - **CAS** with must-not-exist.
    - **Txn:** ≤ 8 compares on version, value or lease, and ≤ 8 ops. Both branches are validated, and the chosen one runs atomically.
    - **Leases:** timestamps come from the command; a global fencing counter; keep-alive from `max(expiry, ts)`; idempotent `LeaseExpire`; revoke deletes the lease's keys.
    - **Counters:** monotonic.
  - **Limits as results:**
    - key ≤ 512 B and value ≤ 256 KiB;
    - 100 000 keys, counters and leases;
    - a 40 MiB state-bytes budget and an 8 MiB dedupe budget, so every reachable state fits a 64 MiB snapshot.
  - **Dedupe** (`dedupe.go`): FIFO by insertion, bounded by entries (10 000) and bytes, and part of snapshots.
  - **Snapshots** (`snapshot.go`, `hash.go`):
    - a version byte plus a canonical `FSMState`;
    - `Restore` validates fully before swapping;
    - `StateHash` is the SHA-256 of the canonical encoding.
  - **Read helpers:** `Get`, `List`, `GetLease`, `IsExpired`, `ExpiredLeaseIDs` and `AppliedIndex`, each judged by the caller's clock where expiry matters.
  - **`NewApplier`** adapts the FSM to 04.02's `node.Applier`.
- **`internal/raftkv/fsmtest`:** a seeded command `Generator` (reusable by 04.08).
- **Lint:** the `raft-fsm` depguard rule now denies `time`, `math/rand`, `crypto/rand`, `os` and `net` in non-test files. A `lint-selftest` fixture proves the rule fires.
- **Docs:** `docs/architecture/raft-fsm.md`, linked from `README.md`.

## 5. Architectural decisions made during implementation

- **Command messages reuse kv.proto's request types.** 04.04 wraps the request it received in a `Command`, so there is no second schema to keep in sync. `Command.meta` is authoritative over the request's own meta.
- **`CommandResult` is a protobuf message.** Dedupe stores results, and snapshots include them, so they need a deterministic encoding. The node's `Result.Data` carries the encoded result.
- **The snapshot is a version byte plus protobuf `FSMState`,** with canonically ordered repeated fields and deterministic marshalling. Lease→key sets are rebuilt from the keys on restore rather than stored, so they can't disagree.
- **Total-bytes budgets** of 40 MiB of state and 8 MiB of dedupe (a review finding). The per-key limits allow about 25 GiB, far over the 64 MiB snapshot limit. Without these budgets, a large state makes every snapshot fail and stops log compaction for good.
- **Map-order safety by construction:** every map iteration goes through `sortedKeys`, and a test type-checks the package to enforce it. A depguard rule keeps out the clock, randomness, OS and network.
- **The `node.Applier` assertion lives in `applier_test.go`**, so the pure FSM package doesn't import the Raft node.

## 6. Deviations from the specification

All of these are clarifications:

- **Result codes:**
  - **`QUOTA_EXCEEDED` added.** §5 asks for the key limits to be "enforced as deterministic results" but names no code. It also covers the counter, lease and byte budgets.
  - **`KEY_NOT_FOUND`** means `expected_version > 0` on an absent key; any other version mismatch is `VERSION_MISMATCH`.
  - **04.04 mapping:** the `00E` §4 API mapping (`CONFLICT`, `NOT_FOUND`, `INVALID_ARGUMENT`) is 04.04's, and is suggested in `raft-fsm.md`.
- **Txn size:** the task says "≤ 8 ops", and kv.proto says "≤ 8 ops in all". So: at most 8 compares, and at most 8 success and failure ops together.
- **Lease TTL:** 1 ms to 24 h. The task sets no range; this bounds `expires_at` arithmetic. Lease owners are ≤ 256 bytes, as are `client_id` and `request_id`.
- **`Apply` at an applied index:** it returns the remembered result when the command has one ("idempotent skip returning cached result when available"), else `ErrAlreadyApplied`. That is the only Go error `Apply` returns.
- **Value compares on an absent key never hold,** as in etcd. That is a review finding: otherwise `value == ""` would also match a key that doesn't exist.
- **CAS delete needs `expected_version > 0` and no `lease_id`** (a review finding).
- **Snapshot error names:** the snapshot size error is `fsm.ErrSnapshotTooLarge`, and its limit is the FSM's own `MaxSnapshotBytes`, equal to storage's 64 MiB. The FSM doesn't import `storage`, which pulls in bbolt.
- **`Apply` returns `*coordinationv1.CommandResult`**, the task's `Result`.

## 7. Known limitations / follow-ups

- **Retries outside the dedupe window re-execute.** The window is 10 000 identities or 8 MiB, whichever is reached first.
- **Snapshot cost:** each snapshot and each `StateHash` encodes the whole state, up to about 56.5 MiB in the worst case.
- **`List` cost:** it sorts the key set on every call, and runs under the read lock that `Apply` waits for. That's fine at coordination scale; a sorted index is the follow-up if `List` traffic grows.
- **Code-review findings declined, with reasons:**
  - **Fencing tokens equal lease ids, and `LeaseRevoke` takes no token.** Tokens order holders (ADR-003); they are not credentials. API authentication (02.05) gates callers. Documented in `raft-fsm.md`.
  - **KeepAlive extends an expired lease that hasn't been removed yet.** Task §4 explicitly allows it, and Postgres fencing keeps it safe (ADR-003). Documented.
  - **`List` performance:** see above.
- **Not done:** porcupine linearizability (`00C` §11) belongs to the KV API paths in 04.04 and 04.08; the FSM's own property is determinism, which is tested.
- **Defects found in earlier tasks:** none.
- **Temporary stubs:** none.
