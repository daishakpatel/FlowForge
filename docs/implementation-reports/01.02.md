## 5. Architectural decisions made during implementation

- **One server per test binary, one database per test.** Starting a container per test costs several seconds; sharing the server and isolating by database is what the task's "unique database per test" implies. Ryuk removes the containers when the binary exits.
- **Separate admin role on the `postgres` server.** `postgres` is the superuser; the app roles `flowforge` and `aiops` own only their databases, so app DSNs from `00E` §6 never carry superuser rights.
- **Ports bound to `127.0.0.1`** so the dev-only credentials are never reachable from the network.
- **Healthchecks use TCP**, because the image's temporary init server only listens on the socket. A container is therefore healthy only after its init SQL has run.
- **`dev-reset` restarts the stack** after dropping volumes, so the init SQL runs again straight away.
- **Integration tests run with `-race`**, as `make test-integration` already did in 01.01.

## 6. Deviations from the specification

1. **Compatible extension, recorded in `00A`:** new variables `FF_DEV_PG_PORT` and `FF_DEV_MD_PORT` (Compose host ports; port 5432 was taken on this machine) and `FF_TEST_MD_DSN` (the Timescale counterpart of `FF_TEST_PG_DSN`, which the task leaves unnamed). All five test and dev variables are now in `00E` §6.
2. **Timescale roles via image environment, not init SQL** (clarification). The task's file list has init SQL only for `postgres`. `POSTGRES_USER=md`, `POSTGRES_DB=marketdata` matches the `00E` §6 DSN `postgres://md:md@…/marketdata`; `md` is that dev server's admin.
3. **The timescaledb extension is installed in every new database** (clarification). The image adds it to `template1`, so `\dx` in `marketdata` and in test databases already shows it. The criterion's "available" is met; later migrations should use `CREATE EXTENSION IF NOT EXISTS`.
4. **Package-level state in `internal/testutil`** (clarification). `pgServer` and `tsServer` cache the shared server (§5); `00C` §8 otherwise forbids package-level mutable variables. The exception is confined to this test-only helper, guarded by a mutex and explained in `pg.go`.
5. **Helper signatures** (clarification; the task names the helpers without signatures):
   - `NewPostgres(t testing.TB) *PG` and `NewTimescale(t testing.TB) *PG`, with `PG{DSN, Database, AdminDSN}`; cleanup is automatic.
   - `WaitFor(t testing.TB, cond func() bool, timeout time.Duration)`.
   - `Eventually(cond func() bool, timeout, tick time.Duration) bool`.
   - `LeakCheck(m *testing.M, opts ...goleak.Option)`, which always ignores the testcontainers Ryuk reaper goroutine.
   - `ApplyMigrations(t testing.TB, dsn, dir string) error`.
6. **`CREATE`/`DROP DATABASE` statements are built as strings** (clarification). Database names can't be bind parameters; the name is generated by the helper and quoted with `pgx.Identifier.Sanitize`.
7. **Files outside the task's list:** `pg_test.go`, `eventually_test.go` and `main_test.go` (unit tests the task's §8 requires, and the leak check), plus `go.sum`. `make lint` now passes `--build-tags=integration`, a change to a 01.01 target. It's backwards-compatible, and without it the integration tests would never be linted.
8. **`.env.example` lists the test variables commented out**, so copying it to `.env` doesn't change test behaviour by accident.
