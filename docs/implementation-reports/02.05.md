## 1. What was implemented

- **API keys** (`internal/api/auth/keys.go`):
  - Format `ff_<keyid>_<secret>`: `keyid` is 12 lowercase base32 characters, the secret 32 random bytes in base64url.
  - Storage is a 16-byte salt plus `SHA-256(salt‖secret)`, compared with `subtle.ConstantTimeCompare`.
  - `GenerateKey`, `HashToken`, `ParseToken`, `ErrMalformedKey`.
- **Authenticator** (`authenticator.go`, `cache.go`):
  - `KeyAuthenticator` reads `Authorization: Bearer …`.
  - `VerifyToken(ctx, token)` is transport-free and also part of the `Authenticator` interface, so it's usable from gRPC.
  - Expiry and revocation checks.
  - A 30 s TTL LRU cache (1024 entries), with `Invalidate` called on revoke.
  - Every rejection gives the same `401 invalid API key`. An unknown key id still does a hash comparison (no timing oracle), and a database error is never reported as 401.
- **Roles** (`principal.go`):
  - Constants for the five roles; `Roles`, `IsServiceRole`.
  - `Allowed`: `viewer < operator < admin`; service roles are valid only for their own route group.
- **Bootstrap** (`bootstrap.go`):
  - A configured `FF_ADMIN_BOOTSTRAP_KEY` must be well-formed. It's stored as admin when no active admin exists; doing so again is a no-op.
  - In dev with no key and no admin, a key is generated, and `main` prints it once past the redacting logger.
  - Wired into `cmd/flowforge-api` before serving.
- **RBAC:**
  - `routes_acl.go` maps every route to its minimum role, from `00E` §9; a route without an entry is admin-only.
  - `rbac.go` middleware returns `403 PERMISSION_DENIED`.
  - The ACL test fails when a route lacks an entry or an entry names no route.
- **Audit** (`audit.go`):
  - The outermost per-route middleware writes an `audit_log` row for every non-GET request and every 401/403 (GETs included).
  - Columns: actor key id and role, `action` = `METHOD pattern`, resource type and id (from `Location`, else the first path parameter), `request_id`, and outcome `ok|denied|error`.
  - `details` holds only `{status, body_bytes}`.
  - A failed write logs at ERROR and increments `flowforge_audit_write_failures_total`; the request proceeds.
- **Rate limiting** (`ratelimit.go`):
  - A token bucket per key on the injected clock: `FF_API_RATE_LIMIT_RPS` (default 50) with burst 2×; `worker` and `ai-readonly` get 4×.
  - An empty bucket is `429 RATE_LIMITED` with `Retry-After`.
  - Health, metrics and the spec endpoint are exempt (outside the chain).
- **API key endpoints** (`apikeys.go`), all admin-only:
  - `POST /api/v1/api-keys`: name, role and optional future `expires_at`; the key is returned once, with `Location`.
  - `GET /api/v1/api-keys`: paginated, never secrets.
  - `DELETE /api/v1/api-keys/{key_id}`: idempotent revoke, 409 for the last active admin, and the cache is invalidated.
- **Persistence:**
  - `queries/api_keys.sql` and `queries/audit.sql`.
  - `persistence.APIKeyRepo` and `persistence.AuditRepo` (the audit recorder), plus `NewAPIKey`, `AuditEntry` and `APIKeyView` (with `Active`).
  - `pg.APIKeyRepo` and `pg.AuditRepo`. `Revoke` row-locks the active admins, so concurrent revocations always leave one.
- **Router:** each `/api/v1` route passes `Audit → Auth → RateLimit → RBAC` as chi inline-group middleware, which sees the matched pattern. The `Deps` gain `DB`, `Tx`, `APIKeys`, `Audit` and `RateLimitRPS`.
- **OpenAPI:** the bearer scheme description; `403` and `429` (with `Retry-After`) on every `/api/v1` operation; the three api-keys operations; `APIKey`, `CreatedAPIKey`, `APIKeyList`, `CreateAPIKeyRequest` and `Role` schemas.
- **Docs:**
  - `docs/api/authentication.md`;
  - `docs/api/README.md` and `README.md` (keys are now required; dev bootstrap);
  - `00E` §6 and §11.1, plus a `00A` amendment;
  - `docs/configuration.md`, `.env.example`, `docs/decisions/versions.md`.

## 5. Architectural decisions made during implementation

- **Per-route middleware:** audit, auth, rate limit and RBAC run as chi inline-group middleware, which executes after route matching. RBAC and audit therefore see the route pattern without re-matching, and an unknown `/api/v1` path is a plain 404 that is neither authenticated nor audited.
- **Audit sits outermost** (before authentication, unlike the task's diagram), so 401 and 403 are recorded. Authentication passes the principal to it through a holder in the request context.
- **One code path for every rejection:** malformed, unknown, wrong secret, revoked and expired all give the same message. Database errors are surfaced as errors (→ 503), never as 401.
- **The last-admin rule lives in the repository:** it's enforced in one transaction with row locks on the active admin keys, not in the handler.
- **Rate limit derivation:** the burst and service-role limits are derived from one variable (§6 item 3).

## 6. Deviations from the specification

1. **Dev bootstrap key printing.** The "redaction exemption flag" is implemented as one line written directly to the log output (past the slog logger, whose redaction masks every `ff_…` key), only when a dev key was just generated. The key is never passed through the logger.
2. **Where the audit recorder lives.** It is `persistence.AuditRepo.Record(ctx, q, AuditEntry)`, with key storage in `persistence.APIKeyRepo` and implementations in `pg` (files outside §7), matching the 02.03 layering. The task's `audit.Record(ctx, …)` names this recorder.
3. **One rate-limit variable.** Only `FF_API_RATE_LIMIT_RPS` exists; the burst is 2× (giving the task's 100) and the service roles 4×. The new variable and the metric `flowforge_audit_write_failures_total` are compatible extensions: `00E` §6/§11.1 and a `00A` amendment.
4. **`VerifyToken` is on the `Authenticator` interface** (the stub implements it too), so "`Authenticator.VerifyToken`" exists literally. `KeyAuthenticator.Invalidate` is reached through a small interface assertion in the revoke handler.
5. **`FF_AUTH_DISABLED`** keeps its 02.04 default (`false`) and stays dev/test-only with a startup WARN (task §5). "Remove the default" (§6 step 3) is read as "authentication is on unless explicitly disabled", which is the case.
6. **Audit `details`** hold only `status` and `body_bytes`. "Redacted body summary" is implemented as the body size: field names could carry user data, and the task forbids bodies.
7. **"Keys cannot elevate their own role"** holds because there is no endpoint that changes a key's role or expiry. Creating keys is admin-only.
8. **Unknown route → admin only** applies to routes registered without an ACL entry. Unregistered paths are 404 before authentication (decision in §5).
9. **02.04 test changes:** `newAPIEnv` now authenticates with real per-role keys (`router` adds the admin key when a request has none). The 401 sweep uses the real authenticator instead of the stub, and `created_by` assertions expect the admin key id instead of `dev`. Every 02.04 assertion about behaviour is kept; only the authentication setup changed, which this task's behaviour change requires. It is listed as its own suggested commit (`00C` §11).

## 7. Known limitations / follow-ups

- **Unauthenticated requests are not rate limited,** and each 401 writes an audit row (a cost amplifier). Documented; a network-level limiter is recommended in front of the API.
- **Rate limits are per instance.** The cache makes cross-instance revocation take effect within 30 s.
- **No key rotation automation and no OIDC** (documented as not covered).
- **Concurrent dev instances** starting on an empty database may each generate a bootstrap key. Dev only; a configured key is idempotent.
- **`flowforge_audit_write_failures_total` has no alert yet** (08.x owns alerts).
- **Not tested end to end:** the 03.01 gRPC interceptor is that task's own; `VerifyToken` is unit-tested.
- **Temporary stubs:** none new; `auth.NewStub` remains as the documented dev switch. **Defects found in earlier tasks:** none. **Skipped tests:** none.
