## 3. Objective

Make execution resilient: retry policy with backoff/jitter and error classification, per-attempt timeouts, detection of lost workers with attempt abandonment and reassignment, and proof that scheduler/API restarts at any point converge.

## 4. Detailed Implementation Requirements

- Replace `TerminalOutcomeHandler` with `RetryOutcomeHandler` (seam from 03.01): on `Failed|TimedOut|Abandoned` decide using the task's `retry_policy`: non-retryable error code or `retryable=false` → terminal (`FAILED`, or `TIMED_OUT` when the final attempt timed out); attempts remain (`attempt_count < max_attempts`) → `RETRY_WAIT` with `available_at = clock.Now() + NextRetryDelay(...)`; emit `task.retry_scheduled` with delay/attempt in payload; else terminal. Abandoned attempts **count** toward `max_attempts`.
- `RetryWait→Queued` promotion in `SchedulerLoop` when `available_at <= clock.Now()` (conditional transition; notify waker).
- `TimeoutLoop` (leader-gated, tick 1 s): attempts `RUNNING` with `deadline_at <= now` → `TIMED_OUT` (conditional on status+token-agnostic since server decides) then `OutcomeHandler`; also enforces `task.timeout_seconds` for QUEUED tasks? **No** — queue wait is not counted (documented).
- `recovery.Loop` (leader-gated, tick 2 s): ask `LeaseProvider.Expired(ctx)`; for each lost worker mark its RUNNING attempts `ABANDONED` and run `OutcomeHandler`; mark worker observation `LOST` (event `worker.lost`). Also a heartbeat-staleness fallback for attempts whose worker is unknown: `last_heartbeat_at` (or `started_at`) older than `3×FF_WORKER_HEARTBEAT + FF_WORKER_LEASE_TTL`.
- API/worker race rules: a report arriving after the server marked the attempt TIMED_OUT/ABANDONED is rejected as STALE_ATTEMPT (already guaranteed by SQL).
- **Crash-consistency harness** (`internal/testutil/failpoint`): named failpoints (`FF_FAILPOINTS=name=error|panic`) compiled in under build tag `failpoint` at points: after attempt insert before task transition, after task transition before event insert (inside tx ⇒ rolled back), mid-`processRun`, between outcome handling steps. Tests kill/restart loops at each failpoint and assert convergence.
- Degraded behavior: all loops treat DB errors as retryable with capped backoff (log, metric `flowforge_loop_errors_total{loop}`), never make partial decisions outside a transaction.

## 5. Technical Design

Retry decision table:

| Outcome | retryable flag / code | attempts left | Result |
|---|---|---|---|
| Failed | retryable & code ∉ non_retryable_errors | yes | RETRY_WAIT |
| Failed | non-retryable (flag or listed code) | — | FAILED |
| Failed | retryable | no | FAILED |
| TimedOut | (always retryable) | yes | RETRY_WAIT |
| TimedOut | — | no | TIMED_OUT (terminal) |
| Abandoned | (always retryable) | yes | RETRY_WAIT (delay = normal backoff) |
| Abandoned | — | no | FAILED with code `WORKER_LOST` |

All timestamps compared in SQL are bound parameters from the injected clock (ADR-021): `WHERE deadline_at <= $now`. Tests drive a `clock.Fake`.

Recovery sequence matches master spec §3.4. The leader acts only on facts reported by `LeaseProvider`; with the PG lease provider these are heartbeats, in 04.07 they become Raft lease expirations — **the Recovery loop must not change** (only the provider).

**Design notes / edge cases:**

- Idempotent marking: abandoning an attempt that already finished is a no-op (0 rows).
- Do not retry tasks whose run is cancelled/cancel-requested: treat as CANCELLED (03.05 completes this; leave a guarded seam now).
- Backoff jitter uses a per-loop seeded `*rand.Rand` injected for tests.

## 8. Testing Requirements

- Unit table: every row of the retry decision table; abandoned counts toward attempts; non-retryable code list honored.
- Integration (fake clock): fail → RETRY_WAIT with `available_at = now + initial_delay` (jitter 0); after `Advance` task QUEUED and reclaimed; backoff sequence 1s,2s,4s capped at max.
- Integration: handler `sleep 10s` with `timeout_seconds=1` → attempt TIMED_OUT at ≈ deadline (+ tick), task retried or TIMED_OUT per policy; late completion rejected.
- Integration: kill worker process mid-task (stop heartbeats) → after lease TTL attempt ABANDONED, new attempt claimed by another worker, final result recorded once; `worker.lost` event present.
- Zombie test: paused worker wakes and calls Complete with the old token → rejected; final task result equals the new attempt's.
- Crash consistency: for each failpoint, crash the scheduler/worker API mid-operation, restart, and assert DB invariants (no task both RUNNING and without RUNNING attempt; no duplicate RUNNING attempts per task; events consistent with states) and eventual completion.
- DB outage: stop Postgres for 5 s while loops run → loops back off, no panic, resume and complete runs afterwards.

General: `make lint` and `make test` must pass; run packages you touched with `-race`; record exact commands and results in the completion report.
