## 3. Objective

Implement data flow between tasks (constrained templates), the `run_if` expression language, and the remediation **rerun** mechanism that resolves the v1.0 'retry loop' contradiction while preserving immutable history.

## 4. Detailed Implementation Requirements

- `internal/workflow/template`: resolver for `${run.input.<path>}`, `${tasks.<id>.result.<path>}`, `${tasks.<id>.status}` placeholders found in string leaves of a task's `config` (recursively through objects/arrays). A string consisting of exactly one placeholder keeps the referenced JSON type; embedded placeholders interpolate as strings. Paths use dotted keys and `[n]` indices. Missing path → `TemplateError{Path}`. Max resolved input size 256 KiB. **Only ancestors** of the task may be referenced.
- `dag.Validate` extension: extract placeholders/expression identifiers and reject references to non-ancestors or unknown tasks (`INVALID_REFERENCE`). Install `ExprValidator` hook.
- `internal/workflow/expr`: small expression language for `run_if_expr` — operands: numbers, strings, booleans, null, paths (`tasks.x.status`, `tasks.x.result.a.b`, `run.input.k`); operators `== != < <= > >=`, `&& || !`, parentheses; hand-written Pratt parser, evaluator returning bool; type errors → evaluation error. Implements `statemachine.ExprEvaluator`.
- Replace the identity `InputResolver` with the template resolver (resolution happens at READY→QUEUED); resolver errors fail the task non-retryably (`INVALID_INPUT`).
- **Rerun**: `POST /api/v1/runs/{run_id}/rerun` body `{task_ids?: [task_key], reason: string}` and convenience `POST …/retry` (= rerun of all head tasks in FAILED/TIMED_OUT). Behaviour: allowed when run is `FAILED|NEEDS_ATTENTION|SUCCEEDED?` → **only FAILED/NEEDS_ATTENTION** (else 409). In one transaction: for each target head task (must be FAILED/TIMED_OUT/CANCELLED) and every *descendant head task not SUCCEEDED*, insert a new `workflow_tasks` row (`status=PENDING`, `supersedes_task_id = old id`, same definition fields, `attempt_count=0`); originals untouched; set run `RUNNING` (clear `completed_at`) with event `run.resumed` including the superseded ids and reason; scheduler proceeds normally via the head-instance rule. Descendants that SUCCEEDED are kept.
- `RunService.Rerun(ctx, RerunParams{RunID, TaskKeys, Reason, Actor})` reused by approval execution (06.06) — returns the created task ids.
- OpenAPI/ACL (operator) updates; `GET /runs/{id}/tasks?include_superseded=true` to view history (default shows head instances only).

## 5. Technical Design

Template example (task `process` consuming `fetch`'s result):
```json
{"config": {"symbols": "${run.input.symbols}", "from": "${tasks.fetch.result.window_start}", "note": "run ${run.input.label}"}}
```
Rerun example (task `quality-check` failed, `on_failure` branch `ai-investigate` ran):
```text
before: fetch✓ validate✓ process✓ quality-check✗ ai-investigate✓ report(always)✓      run=NEEDS_ATTENTION
rerun(task_ids=[quality-check]) → new rows: quality-check#2 (supersedes #1), and descendants not SUCCEEDED
                                  (ai-investigate and report succeeded → kept; ancestors untouched)
after:  quality-check#2 PENDING → READY → … run=RUNNING
```
Head instance = row with no superseder. `DeriveRunStatus` and readiness use head instances only (already implemented in 03.02). The original failed rows remain visible in history and in events (`supersedes` chain).

Expression grammar (EBNF): `expr = or; or = and {"||" and}; and = not {"&&" not}; not = ["!"] cmp; cmp = primary [("=="|"!="|"<"|"<="|">"|">=") primary]; primary = literal | path | "(" expr ")"`.

**Design notes / edge cases:**

- Templates are *not* a general scripting language — no functions, no loops. Keep it that way.
- Evaluation of `tasks.x.result.*` for a SKIPPED/FAILED task: result may be null → missing path error (for templates) / null (for expressions with `==` null allowed).
- Rerun must be atomic and idempotent per `(task superseded id)`: unique `(run_id, task_key, supersedes_task_id)` guards double-click.

## 8. Testing Requirements

- Template table: whole-value type preservation (number/object/bool), interpolation, nested objects/arrays, `[n]` index, missing path error, oversize error, forbidden non-ancestor reference at validation time.
- Expr: precedence, short-circuit, type errors, null comparisons; fuzz: 50 000 random inputs never panic.
- Integration: 3-task chain passes result values downstream; unresolved placeholder → task FAILED `INVALID_INPUT` without retries.
- Integration: market-data-like DAG with `quality-check` failing → `on_failure` branch RUNS, success branch SKIPPED; run status follows handled-failure rule.
- Integration rerun: create new rows with `supersedes_task_id`; originals unchanged; only non-succeeded descendants recreated; run back to RUNNING; second identical rerun request while first pending → 409/no duplicate rows; history endpoint shows both generations.
- Rerun validation: wrong run state, unknown task key, task not failed → 409/404 as appropriate.

General: `make lint` and `make test` must pass; run packages you touched with `-race`; record exact commands and results in the completion report.
