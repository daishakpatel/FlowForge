## 3. Objective

Deliver the core operational views: interactive DAG of a run with live task states, attempt history and log viewer, workers/scheduler/Raft health, and market-data freshness/lag/rate panels.

## 4. Detailed Implementation Requirements

- Run detail: React Flow DAG (auto-layout via dagre/elk), node colors/badges by state (PENDING, QUEUED, RUNNING, SUCCEEDED, FAILED, SKIPPED, CANCELLED, ABANDONED→retrying), edge styles for conditional (`run_if`) edges, superseded/rerun task instances grouped; selecting a node opens a side panel (attempts timeline with fencing token, worker id, error, duration; inputs/outputs JSON viewers with redaction notices).
- Log viewer: virtualized list, tail/follow toggle, level filter, attempt selector, search, download; consumes `GET /api/v1/attempts/{id}/logs` with cursor pagination and SSE `task.log` batches if available (else polling every 2 s while RUNNING); truncated-log indicator.
- Actions (role-gated): cancel run, pause/resume (if supported), retry failed task/rerun, with confirmation dialogs and result toasts; idempotency headers.
- Workers & Cluster page: worker table (status, last heartbeat, running tasks, capabilities), scheduler leader/epoch panel, Raft nodes (leader/follower, term, commit/applied lag), quorum health banner; updates through SSE events (`worker.*`, `scheduler.leader_changed`) + 5 s polling of `/cluster/status`; leader change visible within 5 s.
- Market Data page: freshness gauges per symbol (worst-N), consumer lag per partition (chart), event/aggregate rates, DLQ/duplicate/late counters, backpressure flag, OHLCV chart for chosen symbol/window (lightweight chart lib), data-quality status; 5 s auto-refresh with pause control.
- Performance: DAGs up to 200 nodes render smoothly (memoized nodes, virtualization not required); document limit and fallback list view for > 500 nodes.

## 5. Technical Design

Visual state must equal API state: the DAG derives purely from `GET /runs/{id}` + task list + events; no client-side inference of states. A development-only `/debug/state-diff` view compares rendered state with API (used by the Playwright test).

**Design notes / edge cases:**

- Colors must not be the only state indicator (icons/text too).
- Use the shared error/empty components from 07.01.

## 8. Testing Requirements

- Component tests: DAG renders states/edges from fixtures; conditional edge styling; superseded instances grouped.
- Log viewer: pagination, follow mode, truncation indicator, large log (50k lines) stays responsive (virtualization test).
- Playwright: run a 6-task workflow with a failing task → UI shows retry attempts then FAILED matching API (state-diff view); retry action creates new instance shown in DAG.
- Playwright cluster: kill scheduler leader container (nightly variant) → UI shows new leader within 5 s; worker kill → worker row turns lost.
- Playwright market data: inject lag via processor pause → lag panel and freshness gauge reflect within 10 s.

General: `make lint` and `make test` must pass; run packages you touched with `-race`; record exact commands and results in the completion report.
