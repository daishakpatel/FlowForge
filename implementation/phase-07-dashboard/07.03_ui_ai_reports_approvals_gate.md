## 3. Objective

Surface the AI copilot safely: investigation reports that visually separate observed facts from hypotheses and proposals, evidence links that resolve to real records, and an approval inbox with approve/reject-with-reason; then close the phase with an end-to-end UI test of the full incident loop.

## 4. Detailed Implementation Requirements

- AI page: list of reports (per run) with status; report detail layout: **Summary → Observed facts (each with evidence chip linking to the attempt/log/metric) → Hypotheses (confidence bar, supporting facts) → Recommendations (risk badge, requires-approval, rationale) → Limitations / Insufficient evidence**. Facts vs hypotheses use distinct visual treatment and labels (“Observed” vs “Model hypothesis”). KB citations list with doc/section.
- Evidence chips resolve via the evidence resolver (`/api/v1/ai/evidence/{ref}` proxy or direct link routes) and open the corresponding UI view (attempt log range, worker, pipeline snapshot).
- Approval inbox: pending/decided tabs, action details (exact parameters), current-state check preview (e.g. task is still FAILED), approve (confirm dialog) and reject (reason required), execution result display, expiry countdown; optimistic UI with server reconciliation; SSE `approval.*` updates + toast notification badge in nav.
- Run detail integration: banner “AI investigation available” on failed runs with link; button to request a manual investigation (`POST /api/v1/ai/investigations` proxy → handler path, operator role).
- UI e2e gate (`web/e2e/incident-loop.spec.ts`): stall market data → workflow failure branch → report appears → approve `retry_task`/`replay_range` → run recovers; screenshot artifacts saved.

## 5. Technical Design

Safety UX: the approve dialog repeats the action in plain language and shows parameters verbatim; destructive-looking actions require typing the action name? (**Decision:** only for `risk=high`.) The UI never offers an action type absent from the server allow-list (types come from the API).

**Design notes / edge cases:**

- Render all model-generated strings as text (no HTML/markdown with raw HTML).
- Reports are immutable; show prompt version and mode (mock/live) badge.
