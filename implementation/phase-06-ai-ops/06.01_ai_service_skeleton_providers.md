## 3. Objective

Create the Python AI service (`services/aiops`) with a FastAPI app, Pydantic schemas for the REST contract in `00E §10`, an AI database (`aiops` DB on the pgvector Postgres) migration set, and a provider-agnostic LLM/embedding layer with deterministic mock providers so the whole stack is testable offline.

## 4. Detailed Implementation Requirements

- Project layout: `services/aiops/{pyproject.toml,src/aiops/{api,core,providers,db,graph,tools,kb,eval},tests}`; Python 3.12; deps pinned via `uv`/`pip-tools` lock; ruff + mypy(strict on `core/api`) + pytest; `make ai-lint ai-test` targets; CI job added to existing workflow.
- FastAPI app: `POST /v1/investigations`, `GET /v1/investigations/{id}`, `GET /v1/investigations`, `POST /v1/kb/reindex`, `GET /healthz`, `GET /readyz`, `GET /metrics`; Pydantic v2 models (`InvestigationRequest{run_id?, task_id?, question, context{...}}`, `InvestigationResult` finalized in 06.05 — define now with `status: pending|running|succeeded|failed|insufficient_evidence`). Auth: bearer API key checked against FlowForge (`ai-readonly` is for *tools*; the service itself accepts a service key `FF_AI_SERVICE_KEY`).
- Config via pydantic-settings: `AI_MODE=mock|live`, `AI_LLM_PROVIDER`, `AI_EMBED_PROVIDER`, `AI_DB_DSN`, `FLOWFORGE_INTERNAL_URL`, `FLOWFORGE_AI_KEY`, limits (`AI_MAX_TOKENS`, `AI_MAX_TOOL_CALLS`, `AI_TIMEOUT_S`).
- Provider layer: `LLMProvider` protocol (`complete(messages, tools?, schema?) -> LLMResponse`), `EmbeddingProvider` (`embed(texts)->list[list[float]]`, dimension attr). Implementations: `MockLLM` (scripted/deterministic: given a fixture key derived from the prompt hash returns canned responses; a `ScriptedLLM` test helper that returns a queue of responses and records prompts), `HashEmbedding` (deterministic bag-of-token hashing to 384-d, L2-normalized — gives meaningful cosine similarity for tests), live adapters behind lazy imports: `AnthropicLLM`, `OpenAICompatLLM`, `OpenAIEmbedding` (never imported in mock mode; unit-tested with HTTP mocked). **No network access in default tests** (pytest-socket enforces).
- AI DB migrations (`services/aiops/migrations`, alembic or goose via the Go tooling — choose alembic; document): `kb_documents`, `kb_chunks(embedding vector(384))` with ivfflat/hnsw index, `investigations`, `investigation_steps`, `eval_runs` per `00E §13`. Run with the dev Compose Postgres (pgvector image from 01.02).
- Structured logging (JSON) with request ids; Prometheus metrics via `prometheus-client`; OpenAPI served at `/openapi.json` and exported to `api/openapi/aiops.v1.json` with a drift check.

## 5. Technical Design

Mock-first design (ADR-016): every AI component takes providers by injection. Tests construct `ScriptedLLM([...])` to exercise graph branches deterministically; mock mode in Compose uses fixture-based responses so the demo works without keys. Live mode is opt-in (`AI_MODE=live`) and never required by CI.

Embedding dimension is fixed at 384 in schema; changing provider dimension requires a new migration + reindex (documented, enforced by a startup check comparing provider dim to column dim).

**Design notes / edge cases:**

- Keep the HTTP surface minimal; the graph and tools come later.
- Investigations are persisted from the start so request handlers are stateless.
