## 3. Objective

Build the RAG knowledge base: ingest repo runbooks, architecture docs, schemas and the error catalog, chunk and embed them into pgvector with rich metadata, and provide a LangChain retriever with metadata filters and citation output.

## 4. Detailed Implementation Requirements

- Seed corpus under `kb/` (checked in, versioned): copies/links of `docs/runbooks/*.md`, `docs/architecture/*.md`, `00E` error catalog, event/DB schemas, plus **at least 12 incident-oriented runbook notes** authored here (worker-unavailable, scheduler failover, raft quorum loss, kafka lag, stale market data, DLQ spike, DB latency, outbox backlog, replay procedure, task retry policy, timeout tuning, lease expiry spike). Front matter: `doc_id, title, type, tags[], version`.
- Ingestion pipeline `aiops.kb.ingest`: load markdown → split by headings then size (`RecursiveCharacterTextSplitter` / markdown header splitter; 800 chars, 100 overlap) → metadata `{doc_id,title,path,version,section,chunk_index,type,tags,content_hash}` → embed (provider) → upsert chunks keyed by `(doc_id, chunk_index, content_hash)` (idempotent; unchanged chunks skipped; removed docs/chunks deleted).
- Retriever: LangChain `BaseRetriever` implementation over pgvector (cosine) with filters (`type`, `tags`, `doc_id`) and `k`; returns `Document`s whose metadata include a `citation` `{doc_id,section,path,chunk_index,score}`. Optional MMR (bonus) off by default.
- CLI/endpoint: `python -m aiops.kb.ingest --path kb/`, `POST /v1/kb/reindex` (service key).
- **Retrieval quality set**: `eval/retrieval_seed.jsonl` with ≥ 20 (query → expected doc_id/section) pairs; test computes recall@3 with the deterministic `HashEmbedding`; threshold 0.8 (documented as mock-embedding threshold; live embeddings expected higher).
- Prompt-injection hygiene for KB text: ingestion strips/flags instruction-like content patterns? **Decision:** do not alter content; mark retrieved text as untrusted at prompt time (06.05). Add a seeded *poisoned* doc in test fixtures (`kb_test/poison.md`) used by 06.05/06.07 injection tests.

## 5. Technical Design

Idempotent ingestion allows safe re-runs on every deploy. Deleting a doc removes its chunks. A `kb_ingest_runs` log row records counts. Chunk ids are stable so citations in stored investigation reports remain resolvable until the doc changes (reports also snapshot the cited text).

**Design notes / edge cases:**

- Never log full chunk text at info level.
- Use deterministic ordering for results with equal score.
