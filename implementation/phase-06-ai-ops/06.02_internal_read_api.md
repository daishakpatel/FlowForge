## 3. Objective

Give the AI plane safe, bounded, read-only access to operational facts exclusively through a dedicated internal API (`/internal/v1/*`) protected by the `ai-readonly` role — never direct database access.

## 4. Detailed Implementation Requirements

- Routes (GET only) under `/internal/v1`: `runs/{id}` (summary + task states), `runs/{id}/tasks`, `tasks/{id}/attempts`, `attempts/{id}/logs?tail&since&limit` (redacted, size-bounded), `runs/{id}/events`, `workers` (+ lease status), `cluster/status` (scheduler leader, epoch, Raft health), `marketdata/pipeline`, `marketdata/freshness`, `marketdata/ohlcv` (tight limits), `kafka/lag`, `db/health` (latency probes, pool stats), `definitions/{name}`. Responses include `fetched_at`, `source`, and stable `evidence_ref` ids (e.g. `attempt:<id>`, `log:<attempt>:<offset-range>`) usable as citations.
- Role enforcement: key role `ai-readonly` may call only `/internal/v1/**` GET; every non-GET → 403 `FORBIDDEN_ROLE`; `ai-readonly` calling `/api/v1/**` → 403. Add to the RBAC matrix tests (extend 02.05 table) — **write attempts are exhaustively tested** by iterating every registered route/method.
- Bounds & safety: max response sizes (logs ≤ 64 KiB per call, ≤ 500 lines), max page sizes, server-side redaction (`secret|token|password|api_key` patterns plus config-declared patterns), `Cache-Control: no-store`; per-key rate limit (default 30 rps) and audit entries (`AI_READ`) sampled (log every call at debug, audit summary per investigation).
- Query timeouts (`statement_timeout` 2 s) and read-only DB transaction mode for all handlers (`SET TRANSACTION READ ONLY`).
- `flowforgectl keys create --role ai-readonly --name aiops` documented; Compose seeds a dev key (`ff_ai_dev…`) for the demo only.
- OpenAPI: `api/openapi/internal.v1.yaml` + contract tests; Python client generated (or hand-typed httpx client in 06.04) from it.

## 5. Technical Design

Evidence references are the backbone of the "facts vs hypotheses" rule: every fact the AI reports must carry an `evidence_ref` that resolves via `/internal/v1/evidence/{ref}` (small resolver endpoint returning the original record). The eval harness (06.07) checks that cited refs resolve.

**Design notes / edge cases:**

- Do not reuse handlers from `/api/v1` blindly — wrap them with bounded, redacted variants.
- Include `X-FlowForge-Evidence-Ref` response header on single-object reads.

## 8. Testing Requirements

- Exhaustive route scan: for all registered routes × methods, `ai-readonly` gets 2xx only on documented GETs, otherwise 403.
- Redaction: logs containing `password=hunter2`/bearer tokens are masked in responses.
- Size limits enforced (oversized log request truncated with `truncated=true`).
- Evidence resolver returns the underlying record for each ref type; unknown ref → 404.
- Read-only tx: attempt to trigger a write inside a handler (injected) fails.
- Rate limit returns 429 with `Retry-After`.

General: `make lint` and `make test` must pass; run packages you touched with `-race`; record exact commands and results in the completion report.
