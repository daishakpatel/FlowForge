## 3. Objective

Create the protobuf contracts for the coordination service and Raft peer messages, and implement the durable storage layer behind a `Storage` interface (bbolt-backed) that satisfies the etcd Raft library's `raft.Storage` contract. This task is independent of the workflow engine and may run in parallel with Phases 02–03.

## 4. Detailed Implementation Requirements

- `proto/coordination/v1/kv.proto`: services `KV` (`Get, Put, Delete, List, CAS, Txn, LeaseGrant, LeaseKeepAlive, LeaseRevoke, IncrCounter`), `Cluster` (`Status, Health`), messages per `00E §5.1` (consistency enum `LINEARIZABLE|SERIALIZABLE`, `RequestMeta{client_id, request_id}`, `KeyValue{key,value,version,mod_index,lease_id}`, `Compare/Op` for Txn). Error mapping via gRPC status + `ErrorInfo` (`NOT_LEADER` with `leader_hint`, `NO_QUORUM`, `VERSION_MISMATCH`).
- `proto/coordination/v1/raft.proto`: peer transport service `RaftPeer{ Stream(stream Envelope) returns (stream Envelope) }` carrying marshalled `raftpb.Message` plus `from/to` node ids; snapshot streaming chunking (≤ 1 MiB chunks).
- `internal/raftkv/storage`: `type Storage interface` combining `raft.Storage` (InitialState, Entries, Term, LastIndex, FirstIndex, Snapshot) with persistence ops (`Save(hardState, entries, snapshot)`, `Compact(index)`, `SaveSnapshot`, `LoadSnapshot`, `Close`). bbolt implementation: buckets `meta` (hard state, conf state, first/last index), `entries` (big-endian index → marshalled `raftpb.Entry`), `snap` (latest snapshot metadata + data file path/blob). `fsync` on every `Save` (bbolt default sync; document `NoSync=false`).
- Crash-safety: `Save` writes entries + hard state in **one bbolt transaction**; snapshot save + log truncation transactional; on open, validate invariants (continuity of indices, `commit <= last`, hard state term ≥ last entry term) else return `ErrCorruptStorage` with details.
- In-memory `Storage` for unit tests (wraps `raft.MemoryStorage`) sharing the same interface and conformance test-suite.
- Conformance test suite `storagetest.Run(t, factory)` run against both implementations.

## 5. Technical Design

Raft library contract summary (verify against the library version you import in 04.02 — module path decision in ADR-002 lands in 04.02, but this task needs the `raftpb` types, so **add the dependency now**: verify `go.etcd.io/raft/v3` resolves; fall back to the legacy `go.etcd.io/etcd/raft/v3` path only if needed and record it in `versions.md`):

```text
Ready loop order (per library docs):  persist(Ready.HardState, Ready.Entries, Ready.Snapshot)
                                      → send(Ready.Messages)  → apply(Ready.CommittedEntries) → Advance()
```
Storage must therefore make `Save` atomic and durable before the node sends messages. Keep entries keyed by index; `Entries(lo, hi, maxSize)` returns `raft.ErrCompacted` / `ErrUnavailable` exactly as the library expects.

Data layout (bbolt): `meta/hardstate`, `meta/confstate`, `meta/applied` (last applied index, written with applied batches in 04.03), `entries/<uint64>`, `snap/current` (`raftpb.Snapshot` metadata) and `snap/data` (FSM snapshot bytes). Large snapshots (> 64 MiB) are out of scope; documented limit.

**Design notes / edge cases:**

- Storage is single-writer (the raft goroutine); readers (`Entries` from peer-sending goroutines) must be safe via bbolt read txs.
- Include the node's `cluster id` and `node id` in a `meta/identity` bucket and refuse to open data dirs created by a different identity.
- No `time` usage inside FSM-related code (lint rule from 01.01 applies to `internal/raftkv/fsm`, not storage).

## 8. Testing Requirements

- Conformance (both impls): append/read entries, `Entries` bounds + maxSize, `ErrCompacted`/`ErrUnavailable`, `Term`, `FirstIndex/LastIndex` after compaction, snapshot save/load, hard state round-trip.
- Crash safety: child process performing 10 000 `Save` calls is SIGKILLed at random times 50 times; reopen always passes validation and has a contiguous log whose last entry matches `LastIndex`.
- Corruption: manually corrupt index continuity / term ordering → `ErrCorruptStorage`.
- Identity mismatch refuses to open.
- Benchmark: `Save` of 100 entries latency with fsync — record in report.

General: `make lint` and `make test` must pass; run packages you touched with `-race`; record exact commands and results in the completion report.
