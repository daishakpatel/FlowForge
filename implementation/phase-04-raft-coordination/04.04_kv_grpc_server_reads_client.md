## 3. Objective

Expose the replicated KV as a gRPC service (`flowforge-raft` binary) with linearizable reads via ReadIndex, leader-evaluated lease expiry, a lease-expiry sweeper, request-id retry safety, and a typed Go client that follows leader hints and retries safely.

## 4. Detailed Implementation Requirements

- `cmd/flowforge-raft/main.go`: config (`FF_RAFT_NODE_ID, FF_RAFT_PEERS, FF_RAFT_DATA_DIR, FF_RAFT_CLIENT_ADDR, FF_RAFT_PEER_ADDR`), wires storage, FSM, node, transport, KV/Cluster gRPC servers, obs server, graceful shutdown (stop accepting, transfer leadership if leader — `TransferLeadership` best effort, close storage).
- `internal/raftkv/server`: implements `KV` and `Cluster` services. **Writes** (`Put, Delete, CAS, Txn, Lease*, IncrCounter`): stamp `meta.ts_unix_ms = clock.Now()` on the receiving node (leader; followers return `NOT_LEADER` + `leader_hint`), assign `request_id` if client omitted (client must supply for retries), propose, wait for apply, translate FSM result codes into responses/gRPC statuses.
- **Reads**: `LINEARIZABLE` (default): follower or leader performs `ReadIndex` → wait applied ≥ index → read FSM; only the **leader** evaluates expiry using its clock `nowMs` taken **after** ReadIndex completes; followers forward to leader (or return `NOT_LEADER` hint — choose: return hint; client redirects). `SERIALIZABLE`: read local FSM immediately, response carries `stale=true` and `applied_index`. Responses include `applied_index` and `leader_now_ms`.
- Expiry visibility: reads filter out keys whose lease `IsExpired(leaseID, nowMs)`; `LeaseKeepAlive` on a lease already past expiry **at the leader's clock** → `LEASE_EXPIRED` (client must re-grant) even if not yet physically expired.
- **Lease sweeper** (leader only): every 500 ms, `ExpiredLeaseIDs(now)` → propose `LeaseExpire(id, ts)` (batched ≤ 64/tick) so keys are physically deleted; leader change stops/starts it.
- Deadlines: every RPC honors client deadline; server-side proposal timeout default 3 s (`FF_RAFT_PROPOSAL_TIMEOUT`); `NO_QUORUM`/timeout map to `UNAVAILABLE`.
- `internal/raftkv/client` (`pkg/client/coordination` alias): `Client` with endpoint list, connection pooling, leader cache, retry policy (exponential backoff + jitter, max 5 attempts, overall deadline) that retries only safe cases: `NOT_LEADER` (redirect), `UNAVAILABLE` for **writes with a client-supplied request_id** (safe thanks to FSM dedupe) and for reads. Typed methods: `Get/Put/Delete/List/CAS/Txn`, `LeaseGrant/KeepAlive/Revoke`, `IncrCounter`, `Status`. Every write auto-generates `(client_id, request_id)` with a monotonic request counter.
- Metrics: request counters/latency per op, read-index latency, sweeper activity, `flowforge_raft_write_duration_seconds`.

## 5. Technical Design

```mermaid
sequenceDiagram
  participant C as Client
  participant F as Follower node
  participant L as Leader node
  C->>F: Get(key, LINEARIZABLE)
  F-->>C: NOT_LEADER (hint L)
  C->>L: Get(key, LINEARIZABLE)
  L->>L: ReadIndex → wait applied>=idx
  L->>L: nowMs = clock.Now()
  L-->>C: value (expiry judged at nowMs), applied_index
  C->>L: Put(key, v, request_id=r1)
  L->>L: ts=clock.Now(); Propose(cmd{r1,ts}) → wait apply
  L-->>C: ok
  Note over C,L: timeout/retry with same r1 → FSM dedupe returns original result
```
Linearizability argument: ReadIndex ensures the leader's state reflects every write committed before the read began; writes are acknowledged only after apply. Reads served only by a confirmed leader (CheckQuorum prevents a partitioned stale leader from completing `ReadIndex`).

Clock note: `ts` and `nowMs` come from the leader's clock; a leader change may shift the clock base by NTP skew (bounded ~ms). Lease TTLs ≫ skew (seconds) — document; fencing protects safety (ADR-003).

**Design notes / edge cases:**

- `List(prefix)` returns at most `limit` (default 1000) sorted by key with `next_key` continuation.
- Do not expose `LeaseExpire` as an RPC.
- Client must never retry a write without a request_id (enforced by API shape: `request_id` generated by the client lib).
- gRPC keepalive settings to detect dead leaders quickly.

## 8. Testing Requirements

- Write path: Put/CAS/Txn/Lease results map to proto responses and statuses; request-id retry returns the same result without double apply (verify FSM state version unchanged).
- Reads: linearizable read after acknowledged write always sees the write (10 000 iterations across leader changes); serializable read may be stale and is flagged.
- Expiry: key bound to a lease disappears from reads at `expires_at` per leader clock (fake clock) and is physically removed after the sweeper tick; keep-alive prevents expiry; keep-alive after expiry → LEASE_EXPIRED.
- Failover: kill leader during writes → client transparently succeeds within 2× election timeout (measured, recorded); no duplicate applies.
- No quorum: writes fail `UNAVAILABLE`/`NO_QUORUM`; reads LINEARIZABLE fail; SERIALIZABLE on survivor still answers (stale=true).
- Porcupine linearizability test (60 s, random leader kills, ≥ 20 000 ops) passes; failure dumps history.
- Graceful shutdown: leader steps aside via leadership transfer; client sees at most one redirect.

General: `make lint` and `make test` must pass; run packages you touched with `-race`; record exact commands and results in the completion report.
