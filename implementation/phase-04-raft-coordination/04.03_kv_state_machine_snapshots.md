## 3. Objective

Implement the replicated state machine (FSM): a purely deterministic key-value store with versions, CAS, small transactions, TTL leases (timestamps carried in commands), monotonic counters, request-id deduplication and snapshot/restore — with a determinism test proving replicas converge byte-for-byte.

## 4. Detailed Implementation Requirements

- `internal/raftkv/fsm`: `Command` (protobuf or versioned binary/JSON; choose protobuf `fsm.proto` in `proto/coordination/v1/command.proto`) with `{meta{client_id, request_id, ts_unix_ms}, op}` where `op ∈ Put | Delete | CAS | Txn | LeaseGrant | LeaseKeepAlive | LeaseRevoke | LeaseExpire | IncrCounter | NoOp}`; `FSM.Apply(index uint64, data []byte) (Result, error)`.
- State: `map[string]*Entry{value, version, mod_index, create_index, lease_id}`, `leases map[id]*Lease{ttl_ms, expires_at_ms, keys set, owner, fencing}`, `counters map[string]uint64`, `dedupe` bounded LRU (default 10 000) of `(client_id, request_id) → Result`, `lastApplied`, `nextLeaseID` (counter in state, not random). **The FSM never calls `time.Now()` or any randomness; all time is `meta.ts_unix_ms`.** Lint rule from 01.01 enforces this.
- Semantics: `Put` (optional `expected_version`, optional `lease_id` which must be live → else `LEASE_NOT_FOUND`), `Delete`, `CAS(expected_version; 0 = must not exist)`, `Txn(compare[], success[], failure[])` (≤ 8 ops; compares on version/value/exists/lease), `LeaseGrant(ttl)` returns `lease_id` + fencing value from the **global fencing counter** (monotonic, part of state), `LeaseKeepAlive` extends `expires_at = max(old, cmd.ts) + ttl` (reject if already expired by `cmd.ts` *and* revoked), `LeaseRevoke` deletes attached keys, `LeaseExpire(lease_id, ts)` (proposed by the leader's expiry sweeper) deletes keys only if `expires_at <= ts` (idempotent), `IncrCounter(name)` returns new value.
- Reads (non-Raft path, used by 04.04): `Get/List/GetLease` on a consistent snapshot of the in-memory state under a RW lock; return `{entry, now_ms_hint}`? **No** — expiry judgement needs the *reader's* time; expose `ExpiredLeaseIDs(nowMs) []uint64` and `IsExpired(leaseID, nowMs) bool` helpers so the server layer (04.04) applies the leader's clock to reads.
- Snapshot: deterministic encoding (sorted keys, canonical numbers) of the full state incl. dedupe table and lastApplied → `Snapshot() []byte`; `Restore([]byte)` replaces state atomically; snapshot size limit 64 MiB (error if exceeded); version byte for forward compatibility.
- Applied index handling: `FSM.Apply` refuses `index <= lastApplied` (idempotent skip returning cached result when available) — together with snapshot restore this makes re-delivery safe.
- Checksum: `FSM.StateHash() [32]byte` (SHA-256 over canonical encoding) exposed for determinism tests and an operator endpoint (04.06 `ClusterStatus.state_hash` at a given applied index).

## 5. Technical Design

Lease timing model (ADR-005):
```text
LeaseGrant@ts       → expires_at = ts + ttl
KeepAlive@ts'       → expires_at = max(expires_at, ts') + ttl   (never moves backwards)
LeaseExpire(id, ts) → if expires_at <= ts: delete attached keys + lease   (leader proposes when its clock says expired)
IsExpired(id, now)  → expires_at <= now   (judged by the *leader* at read time; FSM state only stores timestamps)
```
Because only the Applier sees committed commands in log order and uses only command-carried timestamps, two replicas applying the same log produce identical state (**determinism test**: generate 50 000 random commands with seeded RNG and arbitrary (even non-monotonic) timestamps; apply to two FSMs; assert equal `StateHash` at every 1 000 entries; snapshot at random points on one replica, restore on a third, continue applying and compare).

Dedupe: command `(client_id, request_id)` seen before → return the **stored result** without re-executing (safe retries after a timeout in 04.04). Dedupe table is part of snapshots; eviction is FIFO — documented limitation: retries older than the window may re-execute (clients use unique request ids and short retry windows).

**Design notes / edge cases:**

- Result type includes `{ok, error_code, version, mod_index, lease_id, fencing, counter, prev_value}`; error codes: `VERSION_MISMATCH, KEY_NOT_FOUND, LEASE_NOT_FOUND, LEASE_EXPIRED, TXN_TOO_LARGE, INVALID_ARGUMENT`. Failed CAS is a **successful apply with a failure result** (never a Go error — errors would imply non-determinism).
- Key constraints: ≤ 512 bytes; value ≤ 256 KiB; max 100 000 keys (documented) — enforced as deterministic results.
- Iteration order: always sort keys for `List` and snapshot encoding.

## 8. Testing Requirements

- Per-op tables: Put/Get/Delete versions & mod_index; CAS success/mismatch/must-not-exist; Txn compare/success/failure branches and size limit; key/value limits.
- Leases: grant → keys attached → keep-alive extends; expire only when `expires_at <= ts`; revoke deletes keys; put with dead lease fails; fencing counter strictly increasing across grants and across snapshot/restore.
- Counters: monotonic, unaffected by failed commands.
- Dedupe: same `(client,request)` returns identical result with no state change; eviction order deterministic; survives snapshot/restore.
- **Determinism**: two FSMs fed the same 50 000 random commands (seeded; include out-of-order timestamps) have equal `StateHash` at every checkpoint; third FSM restored from a mid-stream snapshot converges.
- Snapshot: round-trip equality; oversize → error; unknown version byte → error; corrupted bytes → error without partially applying.
- Fuzz: command decoder never panics; `Apply` never panics on arbitrary bytes (returns deterministic error result).
- Lint: no `time.Now`/`rand`/map-iteration-dependent output in `internal/raftkv/fsm` (forbidigo + a test asserting sorted iteration helper usage).

General: `make lint` and `make test` must pass; run packages you touched with `-race`; record exact commands and results in the completion report.
