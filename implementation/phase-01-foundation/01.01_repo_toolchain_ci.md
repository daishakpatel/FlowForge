## 3. Objective

Create the FlowForge monorepo skeleton: Go module, lint/format configuration with package-boundary rules, Makefile with the standard targets, GitHub Actions for Go, and the version-recording convention. After this task any agent can clone the repo, run `make lint test`, and see CI green.

## 4. Detailed Implementation Requirements

- Initialize the repository and a single Go module (`go mod init github.com/daishakpatel/flowforge`; pin the `go` directive and `toolchain` to a current stable Go ≥ 1.23 — verify the installed version).
- Copy the blueprint (`implementation/` and `original/`) into the repo root unchanged; these files are read-only for agents except ADR amendments (`00A`) and index/progress checkboxes (`00B`).
- Create ONLY the directories needed now: `cmd/`, `internal/`, `pkg/`, `docs/{architecture,decisions,runbooks,api,testing,implementation-reports}/`, `scripts/dev/`, `.github/workflows/`, `test/{integration,fault,e2e,load,fixtures}/` (each with `.gitkeep`). Do not scaffold empty service packages.
- `.golangci.yml`: enable `govet, staticcheck, errcheck, ineffassign, unused, gofmt, goimports, revive, gosec (medium+), depguard, bodyclose, contextcheck, noctx, errorlint`. Configure `depguard` boundary rules listed in Technical Design.
- `Makefile` with targets: `help, build, test, test-race, test-integration, lint, fmt, tidy, cover, cover-check, proto (placeholder), sqlc (placeholder), openapi-check (placeholder), clean`. Placeholders print a clear 'not yet configured' message and exit 0.
- `scripts/dev/cover-check.sh`: fails if statement coverage of the packages `internal/dag`, `internal/workflow/...`, `internal/scheduler`, `internal/raftkv/...`, `internal/marketdata/processor...` is below 70 % **only for packages that exist** (skips missing ones with a notice).
- `.github/workflows/go.yml`: jobs `lint` (golangci-lint), `test` (`go test -race ./...`, coverage artifact, cover-check), `build` (all `cmd/*`). Use pinned action versions (verify current major versions) and Go version from `go.mod`. Concurrency group cancels superseded runs.
- `.gitignore`, MIT `LICENSE`, `README.md` stub (project summary + link to blueprint + quick start placeholder), `docs/decisions/versions.md` (table: component, version, date, task, notes).
- Add `internal/doc.go` placeholder-free sanity test: a trivial package `internal/version` exposing `Version`, `Commit` (set by ldflags) with a unit test, so CI has something real to run.

## 5. Technical Design

**Package boundary rules (`depguard`)** — encode as deny-lists so later tasks cannot create layering violations:

| Package (glob) | Must NOT import |
|---|---|
| `internal/dag`, `internal/workflow/model`, `internal/workflow/statemachine`, `internal/workflow/template` | `database/sql`, `github.com/jackc/pgx*`, `net/http`, `google.golang.org/grpc`, `internal/persistence/**`, `internal/api/**` |
| `internal/raftkv/fsm` | `time` (use only `time.Duration` via a type alias file allow-list), `internal/persistence/**`, `net/**` — enforces FSM determinism (no wall clock/network); implement via `forbidigo` rule on `time.Now`/`time.Since` in that package |
| `internal/raftkv/**` | `internal/persistence/**`, `internal/scheduler/**` |
| `internal/marketdata/model`, `internal/marketdata/window` | `database/sql`, `github.com/jackc/pgx*`, `github.com/twmb/franz-go/**` |
| `internal/api/**` | `internal/scheduler/**` (API never schedules) |
| `cmd/**` | n/a (wiring only) |

Add `forbidigo` (or equivalent `revive`/`gocritic` rule) banning `time.Now()` outside `internal/clock` and `cmd/**` — everything else takes a `clock.Clock` (introduced in 01.04; until then the rule is enabled with an allow-list that 01.04 tightens).

**Versioning file** `docs/decisions/versions.md` is the single place agents record chosen library versions (see `00C §2.6`).

## 6. Step-by-Step Implementation Instructions

1. Verify Go toolchain availability (`go version`); initialize repo and module; commit blueprint docs under `implementation/` and `original/`.
2. Create the directory skeleton with `.gitkeep` files.
3. Write `.golangci.yml` with the depguard/forbidigo rules from Technical Design; run `golangci-lint run` on the sample package to verify config loads.
4. Write `Makefile` and `scripts/dev/cover-check.sh`; test each target locally.
5. Add `internal/version` package + test.
6. Write the GitHub Actions workflow; validate YAML (e.g. `actionlint` if available).
7. Write README stub, LICENSE, `.gitignore`, `versions.md`.
8. Run `make lint test build`; fix issues; write the completion report.

## 8. Testing Requirements

- `internal/version`: default values; ldflags override verified via a build in the test (`go build -ldflags`) or by function injection.
- Lint config smoke test: a deliberately violating temp file (in a `testdata/` dir excluded from normal lint, exercised by a script `scripts/dev/lint-selftest.sh`) proves `depguard`/`forbidigo` rules fire. Script must be runnable via `make lint-selftest`.
- CI dry validation: workflow YAML lints cleanly.

General: `make lint` and `make test` must pass; run packages you touched with `-race`; record exact commands and results in the completion report.
