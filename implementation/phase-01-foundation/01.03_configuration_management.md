## 3. Objective

Provide one typed, validated, layered configuration system (defaults < file < environment) for all Go services, with secret-safe types, and complete `.env.example` according to `00E §6`.

## 4. Detailed Implementation Requirements

- `internal/config`: struct definitions per service (`API`, `Scheduler`, `Worker`, `Raft`, `Processor`, `Common`), loader `Load[T any](opts) (T, error)` using struct tags `env:"FF_…" default:"…" validate:"…"`; file layer (YAML) from `FF_CONFIG_FILE`; env overrides; durations and lists parsed; unknown file keys rejected.
- `type Secret string` that prints as `***` in `String()`, `GoString()`, `MarshalJSON`, `MarshalText`, logs (slog `LogValuer`), and `%v`; `Reveal()` method explicit.
- Validation: required-in-prod fields (`FF_ADMIN_BOOTSTRAP_KEY` when `FF_ENV=prod`), DSN parse check, positive durations, `LeaderRenew < LeaderTTL/2`, `WorkerHeartbeat < WorkerLeaseTTL/2`, address format.
- `Redacted()` method producing a map for startup logging (all `Secret`s masked).
- Complete `.env.example` with every variable in `00E §6` (grouped, commented, safe dev defaults) and a test that fails if a struct tag env name is missing from `.env.example` (documentation drift guard).

## 5. Technical Design

Config structs are plain data. Services call `config.Load[config.API](config.Options{Prefix:"FF"})` once in `main` and pass sub-structs to constructors — no global config singleton, no `os.Getenv` outside `internal/config` and `cmd/**` (enforce with `forbidigo` on `os.Getenv` in `internal/**` except `internal/config`).

Precedence: defaults < YAML file < env. Errors aggregate (report all invalid fields at once) as `*config.ValidationError{Fields []FieldError}`.

**Design notes / edge cases:**

- Do not add variables not in `00E §6` without extending `00E §6` in the same change.
- Python AI service has its own settings (task 06.01) but must use the same var names listed in `00E §6`.

## 6. Step-by-Step Implementation Instructions

1. Define tags and the reflection-based loader (or use a small vetted library such as `caarlos0/env` + custom validators — record the choice and version).
2. Implement `Secret` and its slog integration; unit-test every leak path (fmt verbs, JSON, slog text/JSON handlers).
3. Implement validation rules and aggregated errors.
4. Define per-service structs with defaults from `00E §6`.
5. Complete `.env.example` and the drift-guard test.
6. Add `forbidigo` rule for `os.Getenv` in `internal/**`.

## 8. Testing Requirements

- Precedence matrix: default only; file overrides default; env overrides file.
- Invalid values: bad duration, bad DSN, negative capacity, `LeaderRenew >= LeaderTTL/2` → single aggregated error listing all.
- Secret never appears in `fmt.Sprintf("%v/%+v/%#v/%s")`, `json.Marshal`, slog JSON and text output.
- Drift guard: every `env:` tag appears in `.env.example`.
- prod mode requires `FF_ADMIN_BOOTSTRAP_KEY`.

General: `make lint` and `make test` must pass; run packages you touched with `-race`; record exact commands and results in the completion report.
