## 3. Objective

Turn persisted ticks into 1m and 5m aggregates with indicators and anomaly flags. Windows are **recomputed from stored ticks** (not incrementally mutated), so replays, duplicates and late events converge to the same result.

## 4. Detailed Implementation Requirements

- `internal/stream/aggregator`: receives *dirty windows* `(symbol, size, start)` from the persister via the `WindowSink` hook (set deduplicated, bounded; coalescing).
- Finalization: windows are (re)computed (a) when dirty and the watermark passed `end + lateness` (**final**), and (b) provisionally every `FF_STREAM_PROVISIONAL_INTERVAL` (default 5s) for freshness (`status=open|final`).
- Recompute: `SELECT … FROM market_ticks WHERE symbol=$1 AND event_time >= start AND < end` → `domain.Aggregate` → upsert `market_aggregates` `ON CONFLICT (symbol,window_size,window_start) DO UPDATE` **only if** `input_hash` differs; update `last_updated_at`, `version++`.
- Late-but-within-bound ticks mark their window dirty again (recompute even if final); later than `max_lateness` handled earlier (DLQ). Counter `flowforge_stream_late_events_total{disposition}`.
- Indicators: compute MA/volatility/anomaly using the preceding `n` final windows read from `market_aggregates`; recompute downstream windows when an upstream final window changes (bounded cascade depth `n`, documented).
- Publish `market.aggregates` events (`market.aggregate.v1`, key=symbol) on change after DB commit (via the outbox pattern lite: aggregator records pending publishes in `market_aggregate_outbox`? **Decision:** publish after commit best-effort and rely on idempotent consumers; document that `market.aggregates` is derived/rebuildable).
- 5m windows derive from stored ticks directly (not from 1m rows) to avoid compounding error.

## 5. Technical Design

Why recompute: incremental updates (add tick to running OHLC) break under duplicates/out-of-order/replay. Recompute-from-ticks costs one range query per dirty window but is trivially idempotent; indexes `(symbol,event_time)` make it cheap (target ≤ 5 ms/window; measured in 09.03).

Convergence property to test: for any ordering/duplication/replay of the same *set* of unique ticks, final `market_aggregates` rows (excluding `last_updated_at`, `version`) are identical.

**Design notes / edge cases:**

- Dirty set must be bounded (max 100k windows); beyond → apply backpressure to the consumer (05.06 wires this).
- Floating tolerance: stored decimals only; no float comparison in hash.

## 8. Testing Requirements

- Golden dataset: known ticks → exact OHLCV/VWAP/MA/vol values (vectors from 05.02 doc).
- Convergence: shuffle/duplicate/replay same unique ticks 50× (seeded) → identical aggregate rows.
- Late within bound: window recomputed and `version` increments; beyond bound: DLQ'd, aggregate unchanged.
- Anomaly spike in injected data flagged exactly on its window; recompute of neighbours stays bounded.
- Idempotent upsert: re-running recompute for unchanged input does not write (verify via xmax/`updated` counter).
