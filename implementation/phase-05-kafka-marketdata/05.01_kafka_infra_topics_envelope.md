## 3. Objective

Add Kafka (single-broker KRaft for dev) to Compose, create an idempotent topic bootstrap, and define the versioned event envelope with JSON Schemas plus the Go envelope/validation library and franz-go client wrapper used by every producer and consumer.

## 4. Detailed Implementation Requirements

- Compose service `kafka` (profile `streaming`; pinned image tag recorded in `versions.md`), healthcheck, internal listener `kafka:9092`, host listener `localhost:19092`. Optional Redpanda-console is NOT added (out of scope).
- `cmd/flowforgectl` subcommand `topics ensure` (or `scripts/dev/topics.go`) that creates topics from `deploy/kafka/topics.yaml` idempotently (create if missing; if present, verify partitions/config and **warn, never shrink**). Topics per `00E §7`: `market.ticks` (6 partitions, key=symbol, 7d), `market.invalid` (3, 14d), `market.aggregates` (3, compacted+delete), `flowforge.workflow-events` (3, key=run_id, 7d), `flowforge.task-events` (3, key=run_id, 7d), `flowforge.dlq` (3). `make topics` wraps it.
- Envelope per `00E §7.2`: `{schema, schema_version, event_id, event_type, occurred_at, produced_at, producer, trace{traceparent}, key, data}`. JSON Schemas under `schemas/events/**` (draft 2020-12): `market.tick.v1`, `market.aggregate.v1`, `flowforge.event.v1` (+ per-event-type `data` schemas), `market.invalid.v1`.
- `pkg/events` (or `internal/events/envelope`): typed `Envelope[T]`, `Marshal/Unmarshal`, `Validate(schemaName, bytes)` using an embedded compiled-schema registry (`embed.FS`; library e.g. `santhosh-tekuri/jsonschema/v5`), compatibility rules enforced by a **schema-compat test**: adding optional fields OK; removing/renaming required fields or changing types requires a new `schema_version` (test compares committed baseline snapshots in `schemas/baseline/`).
- `internal/kafka` wrapper over franz-go: `NewProducer(cfg)`, `NewConsumer(cfg, group)`, configs from env (`FF_KAFKA_BROKERS`, `FF_KAFKA_CLIENT_ID`, TLS/SASL placeholders), idempotent producer enabled, `acks=all`, bounded linger/batch settings, header injection/extraction of `traceparent` (used in 08.01).
- Test helper `kafkatest.Start(t)` (testcontainers-go Kafka KRaft) used by later integration tests.

## 5. Technical Design

Envelope compatibility rules (documented in `docs/architecture/event-schemas.md`):
1. Consumers MUST ignore unknown fields. 2. Producers MUST NOT remove or change the type of a required field within a `schema_version`. 3. A breaking change creates `…v2` and both versions are produced during a deprecation window. 4. `event_id` is globally unique (UUIDv7 or deterministic hash for market ticks, see 05.03). 5. `key` equals the Kafka record key.

Why JSON + JSON Schema (ADR-009): human-debuggable, no schema registry to operate, validation at the edge. Cost: larger payloads and no registry-enforced evolution, mitigated by the compat test.

**Design notes / edge cases:**

- No auto-topic-creation in the broker (`auto.create.topics.enable=false`) so typos fail loudly.
- Keep topic definitions as data (`topics.yaml`), not code.
