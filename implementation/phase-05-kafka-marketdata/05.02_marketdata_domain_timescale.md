## 3. Objective

Implement the pure, fully unit-tested market-data domain: tick model and validation, window arithmetic, OHLCV/VWAP, moving average, rolling volatility, z-score anomaly flag, watermark/late policy decisions — plus the TimescaleDB migrations. No Kafka or I/O in this package.

## 4. Detailed Implementation Requirements

- `internal/stream/domain`: `Tick{EventID, Symbol, Price(decimal), Volume, EventTime, Source, Seq}`; `Validate(tick, now) (Reason)` (reasons: `missing_field, bad_symbol, nonpositive_price, negative_volume, future_timestamp(>5m), too_old(>retention)`). Prices use `shopspring/decimal` (or int64 micro-units — choose and document in ADR-010 amendment; **never float64 for stored prices**).
- Windows: `Window{Size(1m|5m), Start}` with `WindowFor(eventTime, size)` aligned to UTC epoch boundaries; half-open `[start, start+size)`.
- Aggregation: `Aggregate(ticks []Tick, size, start) Window Stats` → `open, high, low, close, volume, vwap, count`; ordering for open/close by `(event_time, seq, event_id)` so results are **order-independent** (deterministic for any input permutation). `input_hash` = SHA-256 over sorted `event_id`s.
- Indicators: `MovingAverage(closes, n)`, rolling volatility = stddev of log returns over n windows (documented formula, population vs sample stated), `ZScore` anomaly: flag when `|close − mean_n| / std_n > k` (defaults n=20, k=3, minimum samples 10).
- Watermark policy: `Watermark = maxEventTime − allowedLateness(30s)`; `Classify(tickWindowEnd, watermark, now) → OnTime | LateRecompute | TooLate`; TooLate beyond `FF_STREAM_MAX_LATENESS` (default 10m) goes to DLQ with reason `too_late` (decision, not drop).
- Timescale migrations in `migrations/marketdata/` (goose, separate DB `marketdata`, extension `timescaledb`): `market_ticks` (hypertable on `event_time`, unique `(event_id, event_time)` per Timescale constraints — document the partition-key requirement), `market_aggregates` (PK `(symbol, window_size, window_start)`), `market_ingest_state`, `market_replay_jobs`; indexes; retention policy (ticks 14d) and compression (>2d) as policy statements; DDL per `00E §12` with any necessary deviation noted.

## 5. Technical Design

Dedupe on a hypertable: Timescale requires the partition column in unique indexes, so uniqueness is `(event_id, event_time)`; because `event_id` is deterministic and `event_time` is part of the event, the same event always maps to the same pair. Document that two events with the same `event_id` but different `event_time` are treated as distinct (a producer bug that is caught by the quality check in 05.09).

Formulas (all in `docs/architecture/market-data-math.md` with worked numeric examples that double as test vectors): VWAP = Σ(price·volume)/Σvolume (undefined → equal to close when volume 0, documented); log return r_i = ln(c_i/c_{i−1}); volatility = sqrt(Σ(r−μ)²/(n−1)).

**Design notes / edge cases:**

- Keep `domain` free of time.Now: pass `now` explicitly.
- Property tests: permuting tick order never changes `Aggregate` output or `input_hash`.
