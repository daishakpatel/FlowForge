## 3. Objective

Provide the market-data source side: a seeded synthetic generator (configurable rate, symbols, fault injection of duplicates/late/out-of-order/invalid ticks), a CSV/JSON historical loader behind the same `Source` interface, and a producer that validates, keys by symbol and publishes with deterministic event ids.

## 4. Detailed Implementation Requirements

- `internal/stream/source`: `Source` interface (`Next(ctx) (Tick, error)` / channel-based `Run`), `Synthetic` (geometric random walk per symbol from a seeded `rand.Source`; config: symbols, rate/s, start time, `clock` mode `realtime|simulated`, injection percentages `dup_pct, late_pct(+max lateness), ooo_pct, invalid_pct, gap_windows`), `FileSource` (CSV/JSON lines; schema documented).
- Deterministic ids: `event_id = hex(sha256(source|symbol|event_time_ns|seq))[:32]`; same seed ⇒ identical stream (golden test).
- `internal/stream/producer`: validates with domain rules **and** the `market.tick.v1` JSON Schema, wraps in envelope, partition key = `symbol`, publishes via franz-go with bounded in-flight; invalid ticks (when injection enabled) are intentionally sent to `market.ticks` anyway under a flag `--allow-invalid` so the processor's DLQ path is testable; otherwise they go to `market.invalid` directly with reason.
- `cmd/flowforge-producer` (long-running or `--count N` bounded mode, exits 0 when done) — also reusable as a library by task handlers; flags/env: `FF_PRODUCER_RATE`, `--symbols`, `--seed`, `--start`, `--duration`, `--inject dup=1%,late=2%,...`.
- Metrics `flowforge_producer_events_total{result}`, `…_publish_latency_seconds`.

## 5. Technical Design

Simulated clock mode generates event times from a virtual clock, allowing a day of ticks to be produced in seconds for tests and load runs (`--speedup`). In `realtime` mode event_time≈now.

Ordering guarantee: per symbol (partition key) Kafka preserves order; injected `ooo` ticks are *event-time* disorder inside that order, which is what the processor must handle (not a Kafka reordering).

**Design notes / edge cases:**

- Never use global `math/rand`; every random decision comes from the seeded source.
- Bound producer memory: use `ProduceSync` batches or semaphore-limited async.

- Golden: seed 42, 3 symbols, 1 000 ticks ⇒ fixed SHA-256 of stream; changes only with intentional version bump.

- Per-symbol ordering test through real Kafka: consumer sees each symbol's ticks in produced order.
- Invalid injection routes as configured; schema failures never reach `market.ticks` unless `--allow-invalid`.
- FileSource parses CSV and JSONL fixtures; bad rows reported with line numbers.
