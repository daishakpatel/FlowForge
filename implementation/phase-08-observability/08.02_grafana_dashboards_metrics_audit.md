## 3. Objective

Provision Prometheus + Grafana with dashboards for the nine operational areas, and audit that every metric promised in `00E §11` is exported with sane labels (no high-cardinality or sensitive labels).

## 4. Detailed Implementation Requirements

- Compose profile `observability`: Prometheus (scrape configs for api, scheduler×N, workers, raft×3, processor, producer, aiops, kafka-exporter, postgres-exporter, timescale exporter), Grafana with provisioned datasources and dashboards from `deploy/grafana/dashboards/*.json` (generated with Grafonnet/jsonnet or hand-maintained JSON validated by a script).
- Dashboards (v1.0 §17.3 nine areas): (1) Platform overview, (2) Workflow runs/tasks (throughput, durations p50/p95/p99, failures by reason), (3) Scheduler & leader/epoch, (4) Workers & leases, (5) Raft cluster, (6) Kafka consumer lag & producer, (7) Market-data pipeline (freshness, rates, late/dup/DLQ), (8) Outbox & DB (latency, pool), (9) AI copilot (investigations, tool calls, latency, approvals). Template variables (`job`, `instance`, `symbol` top-N), links between dashboards, annotations for leader changes.
- `scripts/ci/check-metrics.go`: scrapes every service in an integration run, compares exported names/labels against the catalogue in `00E §11` (machine-readable `metrics/catalogue.yaml` derived and committed): fails on missing metric, undeclared `flowforge_*` metric, or forbidden label (`run_id`, `task_id`, `event_id`, `user`, `key`, free-text) — **cardinality guard**; allowed unbounded-looking labels (`symbol`) guarded by config cap.
- Dashboard validation: JSON schema/lint, every panel's PromQL references metrics that exist in the catalogue (static check), provisioning smoke test (Grafana API: all dashboards load without error).
- Retention/limits: Prometheus retention 7d dev; recording rules for expensive queries (`deploy/prometheus/recording.yml`).

## 5. Technical Design

Catalogue-first: `metrics/catalogue.yaml` is the single source (name, type, labels, owner service, description). Code, dashboards and alerts are checked against it, so renames cannot silently break dashboards.

**Design notes / edge cases:**

- Dashboard JSON committed deterministic (sorted keys, no volatile ids) to keep diffs reviewable.
- Exporter images pinned.
