## 3. Objective

Prove the system behaves as documented when dependencies fail: execute every row of the degraded-behavior matrix (master spec §6.2), cross-component chaos scenarios with invariant checking, and SIGTERM/graceful-shutdown tests for all services.

## 4. Detailed Implementation Requirements

- Chaos harness `test/chaos/` using Docker control (`dockerctl` from 04.08) + Toxiproxy: scenario DSL (setup workload → inject fault(s) → hold → heal → verify invariants), timeline log, artifacts on failure (service logs, DB dump of key tables).
- Invariant checker `test/chaos/invariants`: (I1) no task has two SUCCEEDED attempts accepted; (I2) every terminal run's tasks consistent with DAG/`run_if` semantics; (I3) fencing: no attempt result accepted with stale token; (I4) outbox: every state change has a corresponding event (eventually); (I5) market aggregates equal golden for the injected data; (I6) approvals executed at most once; (I7) leader uniqueness (metric sum ≤ 1 at all samples after settle).
- Degraded matrix rows (one test each, expected vs observed table in `docs/testing/fault-report.md`): Postgres down/slow; Timescale down; Kafka down; Raft quorum lost; Raft single node loss; scheduler leader loss; all schedulers down; API instance loss; worker loss mid-task (+ network partition worker↔API with later zombie completion); AI service down; AI model/live provider failure (mock error injection); disk-full simulation on Raft node (read-only fs) if feasible; clock skew injection on leader.
- Combined scenarios: rolling restart of everything under load; leader scheduler killed during outbox publish; worker killed while Kafka down; Raft quorum loss during a burst of task completions; repeated random single-fault injection soak (30 min nightly, 5 min in PR-label CI) with invariants checked continuously.
- Graceful shutdown tests (NFR-REL-02): SIGTERM to API (drain in-flight requests, readiness false first), scheduler (release leadership, stop loops), worker (stop polling, finish or hand back running tasks per policy `drain|abandon`, deregister lease), Raft node (leader transfer), processor (drain+commit), AI service (finish or persist state) — each with timing and exit-code assertions.
- Report generation: aggregates results from 03.09, 04.08, 05.10, 06.07 and this task into `docs/testing/fault-report.md` (master expected-vs-observed table).

## 5. Technical Design

Matrix row definition (each documented as `fault → expected degraded behavior → recovery condition → test id → observed`): the row passes only if user-visible behavior matches (e.g. “Kafka down: workflows continue; outbox backlog grows; alert fires; backlog drains on recovery”) **and** invariants hold. Failures are defects to fix in the owning component (minimal compatible fixes, documented), not test relaxations.

**Design notes / edge cases:**

- Chaos tests are slow: run subset in PR (labelled), full nightly.
- Always heal faults in `defer` / cleanup to avoid poisoning later tests.
