## 3. Objective

Measure the targets in master spec §6.1 under a documented methodology (hardware, versions, config, warm-up, percentile definitions) and report results honestly — including misses with analysis.

## 4. Detailed Implementation Requirements

- Methodology doc `docs/testing/benchmark-methodology.md`: environment capture script (CPU, RAM, disk, Docker/Go/Postgres/Kafka versions, config hash), warm-up (60 s), steady state (≥ 5 min), repetitions (≥ 3), percentile computation (HDR histograms, coordinated-omission avoidance via scheduled arrival rates), result file schema, comparison rules.
- Load generators (`test/load/` in Go using the real client libs, or k6 for REST): (L1) workflow throughput: N concurrent runs of a 10-task DAG, measure runs/s and task dispatch latency (`queued→leased` p50/p95/p99); (L2) worker scale: 10/50/100 simulated workers (lightweight fake workers) polling; (L3) API: create-run and status read latency at fixed arrival rates; (L4) outbox→Kafka lag under event load; (L5) stream ingest: ticks/s sustained to Timescale with aggregation (synthetic simulated-clock producer), end-to-end freshness p95; (L6) Raft: write latency p50/p99, linearizable read latency, throughput; failover time distribution (20 trials); (L7) scheduler failover time distribution; (L8) AI investigation latency in mock mode (pipeline overhead only).
- Profiling hooks: pprof endpoints (guarded), `make profile-*`; capture CPU/heap for the slowest scenario and record findings (bottleneck list vs predicted C-section of the audit `00D`).
- Results: `docs/testing/performance-report.md` + `docs/testing/results/*.json`; table of each §6.1 target vs measured with PASS/MISS and analysis for each MISS (what limits it, what would fix it, whether accepted). No tuning to hide results; any tuning applied before the final run is listed in the report.

## 5. Technical Design

Targets are stated in master spec §6.1 (e.g. Raft failover ≤ 3 s, scheduler failover ≤ 10 s, dispatch p95, ingest rate). The report format intentionally leads with misses. Benchmarks run on the documented dev machine/CI runner class; absolute numbers are environment-specific and are not promised elsewhere in the docs.

**Design notes / edge cases:**

- Do not use unrealistically tiny payloads that flatter results; document payload sizes.
- Repeat runs to estimate variance and report ranges.

## 6. Step-by-Step Implementation Instructions
