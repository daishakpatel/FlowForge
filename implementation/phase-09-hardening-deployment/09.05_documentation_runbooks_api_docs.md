## 3. Objective

Finish the documentation so a new engineer or operator can understand, run, operate and troubleshoot the system: top-level README, architecture overview, ≥ 9 runbooks, API reference, testing guide, known limitations and an operations guide.

## 4. Detailed Implementation Requirements

- `README.md`: what/why, architecture diagram (Mermaid), quickstart (`make demo`), feature matrix (existing vs optional), repo map, links.
- Architecture docs consolidated: `docs/architecture/overview.md` (components, authority split, data flows, failure semantics) linking each per-component doc written in earlier tasks; ADR index kept in sync.
- Runbooks (each: symptoms, impact, diagnosis steps with exact commands/dashboards/queries, mitigation, verification, escalation, related alerts): worker unavailable; scheduler failover/no leader; Raft quorum loss; Kafka consumer lag; stale market data; DLQ spike; outbox backlog; Postgres degraded/failover; task retry storm; replay procedure; AI service down; approval backlog; certificate/key rotation. (≥ 9; each linked from alerts — 08.03 check passes.)
- API reference: rendered OpenAPI (Redoc static build) for public and internal APIs; AI service OpenAPI; gRPC protos documented (buf docs); examples with curl for main flows.
- `docs/testing/README.md`: test pyramid, how to run each suite, CI map, links to reports. `docs/limitations.md`: honest list (at-least-once only, single-region, static Raft membership, JSON events w/o registry, mock-LLM eval caveat, etc.). `docs/operations.md`: config reference generated from `00E §6`/config structs, upgrade/migration procedure, backup/restore (Postgres, Timescale, Raft data dir) with tested commands.
- Docs QA: link checker (`lychee` or script), Mermaid syntax check (mmdc), commands-in-docs smoke test for quickstart, config reference drift check.

## 5. Technical Design

Docs are code: generated parts (config reference, OpenAPI HTML, metrics catalogue table) come from sources and are verified by CI so they cannot drift.

**Design notes / edge cases:**

- Prefer exact commands copied from tests/scripts over hand-typed ones.
- Do not claim capabilities beyond what tests demonstrate.
