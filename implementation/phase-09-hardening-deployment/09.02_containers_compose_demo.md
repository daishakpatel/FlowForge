## 3. Objective

Finalize deployable artifacts: multi-stage, non-root, pinned images for every service, a coherent full-stack Compose with profiles and healthchecks, and `make demo` that seeds data and runs the headline scenario unattended.

## 4. Detailed Implementation Requirements

- Dockerfiles for `api, scheduler, worker, raft, processor, producer, aiops, web (nginx)`; distroless/static or alpine final stages, non-root UID, read-only root fs where possible, `HEALTHCHECK`, pinned base digests/tags in `versions.md`, build args for version/commit, reproducible-ish builds (`-trimpath`, `-ldflags`).
- Compose profiles: `core` (postgres, timescale, api, scheduler×1, worker×2), `ha` (scheduler×3, raft×3), `streaming` (kafka, processor, producer-on-demand), `ai` (aiops, mock mode), `observability` (prometheus, grafana, jaeger, alertmanager, exporters), `ui` (web), `full` = all. Healthchecks and `depends_on: condition: service_healthy`; resource limits; named volumes; startup order and migrations job (`migrate` one-shot).
- `make dev-up|dev-down|dev-reset|demo|demo-failure`: `demo` = bring up `full`, apply migrations/topics/KB ingest, seed definitions, run `market-data-hourly` (success), then run failure scenario (stall data → AI report → approval prompt printed with the UI URL), print a guided summary. `scripts/demo/*.sh` idempotent; exits non-zero on any step failure (CI nightly).
- Image scanning in CI (`trivy image`, HIGH+ fail; exceptions in allowlist), image size report, `docker compose config` lint, `hadolint`.
- Fresh-clone verification: `scripts/ci/fresh-clone-check.sh` (clones, `make dev-up test`) used in nightly.

## 5. Technical Design

Profile composition keeps laptops light: `core` ≈ 2 GB RAM; `full` documented minimum (e.g. 8 GB). Services read config from env with sane Compose defaults so `docker compose --profile full up` works with zero edits.

**Design notes / edge cases:**

- Run containers as non-root; verify with a test that `id -u` != 0.
- No secrets baked into images or committed compose (dev keys are labeled dev-only).
