## 3. Objective

Move from dev-trust to production-grade transport and secret hygiene: optional TLS everywhere with mTLS for internal gRPC/Raft links, secrets from files/env (never images), API-key rotation/revocation workflows, and automated vulnerability and secret scanning.

## 4. Detailed Implementation Requirements

- Certificate tooling: `scripts/dev/gen-certs.sh` (or `flowforgectl certs dev`) creates a dev CA and per-service certs (SANs for Compose DNS names); config keys `FF_TLS_CERT/KEY/CA`, `FF_TLS_CLIENT_AUTH=require` for internal listeners.
- Apply TLS: REST (server TLS; optional), worker gRPC (mTLS option + API key), Raft peer and client gRPC (mTLS), Kafka (SASL/TLS config plumbing, documented; dev stays plaintext), Postgres `sslmode` configurable, AI→FlowForge internal API over TLS option. Default dev profile stays plaintext; `profile=secure` Compose override turns everything on and is tested.
- Secrets: support `*_FILE` env convention (read secret from mounted file) for all DSNs/keys; startup refuses weak defaults when `FF_ENV=production` (default admin key, empty secrets, plaintext listeners unless explicitly allowed); redact config dump.
- API keys: rotate (`flowforgectl keys rotate`), revoke (immediate; verify cache TTL ≤ 30 s), expiry support, last-used tracking; audit entries; rate-limit/lockout on repeated invalid keys (IP + prefix).
- Scanning in CI: `govulncheck`, `pip-audit`, `npm audit` (high+), `gitleaks`, `trivy fs` and later image scan (09.02); allowlist file with expiry and justification for accepted risks; SBOM generation (`syft`) artifact.
- Security review checklist `docs/security/threat-model.md` (STRIDE per component), summarizing mitigations and residual risks incl. AI plane (ties to 06.04) and Raft trust boundary.

## 5. Technical Design

Trust boundaries: client↔API (API key, TLS), worker↔API (API key + mTLS option), API/scheduler↔Raft (mTLS), AI↔internal API (`ai-readonly` key), Kafka/DB (network + credentials). Fencing (ADR-003) remains the safety backbone even if a credential leaks: stale actors cannot corrupt state, though a stolen valid key can still act within its role (documented).

**Design notes / edge cases:**

- Never log secrets or cert private keys.
- Plaintext remains available for local dev, but production mode enforces secure defaults.

## 8. Testing Requirements

- Secure profile integration: full workflow + Raft cluster + AI loop pass with mTLS enabled.
- Negative: client without cert rejected by Raft/worker gRPC; expired cert rejected; wrong CA rejected.
- Production guard: starting with default admin key and `FF_ENV=production` fails with clear error.
- Key revocation: revoked key rejected within 30 s (measured); rotated key old/new overlap behaves as documented.
- Brute-force: N invalid attempts → 429/lockout and audit entries.
- CI scanners run; seeded vulnerable dep (in a test branch/fixture) is detected.

General: `make lint` and `make test` must pass; run packages you touched with `-race`; record exact commands and results in the completion report.
