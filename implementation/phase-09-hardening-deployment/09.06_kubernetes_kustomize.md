## 3. Objective

Provide Kustomize base and overlays to deploy FlowForge on Kubernetes (kind/minikube validated), mapping the Compose topology to Deployments/StatefulSets with probes, resources and config. **Optional**: skip without affecting later tasks.

## 4. Detailed Implementation Requirements

- `deploy/k8s/base`: StatefulSet for Raft (3 replicas, PVCs, headless service, stable DNS peers), Deployments for api (HPA), scheduler (3 replicas), worker (HPA), processor, aiops, web; Services; ConfigMaps; Secrets templates (no real secrets); migration Job; PodDisruptionBudgets (Raft maxUnavailable 1); probes (readiness/liveness/startup) from existing health endpoints; securityContext (non-root, readOnlyRootFilesystem); NetworkPolicies; resource requests/limits.
- Overlays: `dev` (kind, single replicas except Raft), `prod-example` (replicas, anti-affinity, ingress, external Postgres/Kafka endpoints). Backing stores (Postgres/Kafka) documented as external or via example operators — not re-implemented.
- Validation: `kustomize build` for each overlay, `kubeconform`/`kubectl apply --dry-run=server` on kind, optional smoke on kind (`make k8s-smoke`) running the workflow e2e.

## 5. Technical Design

Raft on Kubernetes: pod ordinal → node id; peer list from headless-service DNS; PodManagementPolicy `Parallel`; PDB prevents voluntary loss of quorum. Scheduler replicas rely on Raft election (no k8s leader election).

**Design notes / edge cases:**

- Optional enhancement (tag O in master spec).
- Do not add Helm; Kustomize only.
